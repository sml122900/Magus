# 내 정보 '문서 업데이트' 화면 + 내 정보 올리기 없애기 (2026-10-10, 사용자 요청)

## Problem

- 문서를 Magus에 넣는 길이 셋이었다: 내 정보 › 올린 파일의 '올리기', 게시판 글의 첨부, (없앤) '+ 프로젝트'의 문서 올리기.
  같은 원고가 올린 파일과 첨부 두 곳에 흩어지고, 저자는 "고친 원고를 어디에 올리지?"를 매번 정해야 했다.
- 고친 원고를 올리는 것(수정본)은 "파일을 올린 뒤 Claude에게 '수정본 올렸어'"라는 두 단계였고, 어느 파일이 어느 책의 원본인지 화면에서 보이지 않았다.
- 아버님의 원고 원본이 예전 올린 파일(inbox)에 있다. 지우면 안 된다.

## Action

### 1. 원칙

- **책의 첨부는 모두 게시판 글의 첨부가 기준이다.** 새 문서는 글에 첨부해서 넣는다.
- 내 정보 › 올린 파일의 '올리기'를 없앤다(화면·라우트·스크립트). 예전 주소로 POST가 오면(`/inbox/upload`·`/inbox/delete`) 410과 한국어 안내로 거절한다.
- **예전 올린 파일은 지우지 않는다.** 웹의 '지우기'도 없앤다(그 파일이 아버님 원고의 원본이다). 올린 파일은 '문서 업데이트'에서 바꿀 수만 있고, 바꾼 이전 파일은 휴지통에 간다.
- 도구(files_list·book_import의 '첨부:<id>'·예전 올린 파일 이름)는 그대로 읽는다.

### 2. 내 정보 › 문서 업데이트(`/me/documents`, 메뉴 이름 그대로)

- 지금까지 올라간 문서를 한곳에: 게시판 첨부 문서(docx·pdf·txt·md, 글과 문헌 글) + 예전 올린 파일. 새것부터.
- 줄마다: 파일 이름 · 프로젝트 · 노드 · 책 · 글 제목(글로 가는 링크) · 올린 시각 · 크기 · [업데이트].
  - 예전 올린 파일은 프로젝트·노드·책·글이 없다('—'). 올린 문서의 원본이면 '「프로젝트」 올린 문서 원본 · 수정본 E3'.
  - 원본 판정: 파일의 sha256이 어느 프로젝트의 판(edition) sha256과 같으면 그 프로젝트의 원본이다(점검 16-1의 '이미 가져옴'과 같은 방법).
    여러 판·프로젝트와 같으면 가장 늦게 올린 판. 게시판 첨부도 같은 방법으로 원본을 알아본다.
- 찾기 칸(`?q=`): 파일 이름·프로젝트·노드·책·글 제목에서 글자 그대로 포함(대소문자 무시) — 앞 글자·가운데 글자 모두 맞는다.
- 사용량 줄(N MB / 한도)은 옛 올린 파일 화면에서 옮긴다. 옛 `/me/files`·`/inbox`는 이 화면으로 넘긴다.

### 3. 업데이트(줄마다 [업데이트], 글 보기의 ✎ 고치기에서도 같은 동작)

- 새 파일을 고르면 그 문서 자리를 새 파일로 바꾼다.
  - 게시판 첨부: **같은 첨부 id 자리에 새 파일**을 둔다(글 안의 순서·링크·대화의 '첨부:<id>'가 그대로). 이전 파일은 새 휴지통 id로 첨부 휴지통에 가고,
    프로젝트 휴지통에서 되살리면 그 글에 첨부 하나로 돌아온다(지금 첨부와 겹치지 않는다).
  - 예전 올린 파일: `inbox/<새 이름>`에 두고, 이전 파일은 `trash/inbox/<휴지통 id>/<이름>`으로. 프로젝트 목록의 휴지통(`/shelf/trash`)에
    '올린 파일 「이름」'으로 보이고 되살린다(같은 이름이 있으면 거절).
- 파일 이름 칸: 고른 파일의 이름(확장자 뺀 부분)으로 미리 채우고 고칠 수 있다. 확장자는 고른 파일의 것으로 고정(칸 옆에 보인다).
  금지 문자(폴더 구분자·`:*?"<>|`·제어·서식 문자, 200바이트 넘음, 예약 이름)는 자르지 않고 거절한다. 칸이 비면 고른 파일 이름 그대로.
- 형식: 글의 첨부로 받는 형식(문서 업데이트 화면은 docx·pdf·txt·md), 올린 문서의 원본이면 docx·pdf.
- 글 제목: 그 글의 제목이 이전 파일 이름(확장자 포함 또는 뺀 것)과 같으면 같은 꼴(확장자 있음/없음)로 새 이름으로 바꾼다. 다르면 그대로.
  제목이 비어 있는 글은 보일 때 첫 첨부 이름을 쓰므로 저절로 따라간다. 문헌 글은 제목이 서지라 바꾸지 않는다.
- 다시 만드는 것: 첨부 글자(`.text/`, 20초 안에 못 뽑으면 '나중에'), 썸네일(`.thumb/`, 볼 때 만든다), 찾기 색인(그 글), 인용 상태 캐시(수정본일 때).
- **올린 문서의 원본이면 업데이트가 곧 수정본 올리기다**(예전 올린 파일이든 게시판 첨부든). `book_import new_edition`과 같은 규칙:
  - 같은 파일이면 "이미 올린 파일입니다"로 멈춘다. 장 제목이 30% 미만 겹치면 멈추고 알린다(그때만 '같은 책이 맞습니다' 칸이 보이고, 체크하고 다시 고르면 올린다).
  - **먼저 수정본을 만들고, 성공해야 파일을 바꾼다.** 멈추면 아무것도 바뀌지 않는다.
  - 결과(수정본 번호, 바뀐 장·새 장·빠진 장 수)를 화면 위 한 줄로 보이고 리포트로 가는 링크를 단다.
- 크기 한도(글의 첨부 `MAX_ATTACH_MB`, 예전 올린 파일 `MAX_UPLOAD_MB`, 사용자 전체 `MAX_USER_MB`)·받은 임시 파일에서 흘려 쓰기·CSRF·주인 확인(남의 첨부·파일은 404)은 기존 업로드와 같다.
  본문 한도(`Web.body_limit`): `/me/documents/update`는 두 한도 중 큰 것 + 1MB.

### 4. 같이 고치는 것

- 수정본을 올려도 프로젝트 제목·부제·영문 제목을 바꾸지 않는다. 문서 속 제목이 다르면 리포트에 "문서 제목이 다릅니다(바꾸지 않음): 「…」"만 적는다.
  (book_import에 저자가 title·subtitle을 직접 준 경우만 바꾼다.)
- 대화 출력의 장 상태(draft·revising·done)를 웹과 같은 초안·고치는 중·완성으로(전체 현황 줄, book_read_chapter·book_write_chapter의 status 값). 입력은 그대로 draft|revising|done.
- 수정본 리포트의 "그대로 둔 것: … 생각·문헌·문체" → "다른 책의 글". 리포트·도구 출력에서 서버 내부 경로(`users/default/…`, `removed/`, `versions/`, `original/…`)를 빼고 화면 이름으로.
- category_search에 project를 주면 머리에 "(모든 책)" 대신 "(「프로젝트」의 책)".

### 5. 문구

- instructions 규칙 7의 '수정본 올렸어': 먼저 book_outline 수정본 줄을 본다(문서 업데이트로 바꿨으면 이미 수정본이다). 아니면 게시판 글에 첨부한 문서를 files_list에서 찾아 올린다.
- files_list·category_put(file) 설명과 응답, book_import의 응답: '올린 파일에 두었다'를 '게시판 글에 첨부'와 '예전에 올린 파일'로.
- **도구 설명·instructions가 바뀌므로 커넥터 다시 연결 + '항상 허용' 다시 확인이 필요하다.**
- docs/help, 도움말 챗봇 화면 이름(`documents` = 문서 업데이트), docs/onboarding-father.md 5절·7절: "Word에서 고치고 → 내 정보 › 문서 업데이트 → 그 문서의 [업데이트] → 파일 고르기".
