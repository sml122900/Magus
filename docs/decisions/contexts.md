# 종류를 없애고 '컨텍스트'로 — 사용자 결정 #96 (2026-10-08, 확인 대기)

> #94의 책 종류(원고 책·모음 책·문서 책)와 생각·문체·문헌의 구분을 저자에게 보이는 곳에서 없앤다. #95(프로젝트·지도·노드)는 그대로 쓴다.
> 구현: `src/magus/contexts.py`(컨텍스트 규칙·처음 제공하는 넷·응답 머리), `src/magus/store/contexts.py`(자주 쓰는 컨텍스트·붙이기),
> `src/magus/category/tools.py`·`category/books.py`(글 넣기·찾기·지우기, 책 고르기), `src/magus/book_migrate.py`(이전),
> `src/magus/webcontexts.py`(웹의 컨텍스트 칸·`/me/contexts`). 문구 전후·instructions·도구 설명 전문: `docs/decisions/contexts-texts.md`.
> **서버 배포 안 함**(묶음 배포 `docs/deploy.md` 2-2절).

## Problem

- 책에 종류(원고 책·모음 책·문서 책)가 있고, 모음 책 안에서도 생각·문체·문헌이 서로 다른 도구·저장 형식·화면을 썼다.
  저자는 종류를 외워야 하고, 새로운 묶음(신문 기사, 강의 메모)을 만들면 Claude가 그것을 어떻게 읽어야 할지 알릴 길이 없었다.
- 원하는 것(사용자): 모두 '글'로 저장하고, AI가 어떻게 읽을지는 저자가 적는 '컨텍스트'에 둔다(예: "이 문서는 논문으로서 학술적인 문서야.").
  대부분은 컨텍스트 없는 일반 메모. 자주 쓰는 컨텍스트는 등록해 두고 단추로 붙인다.
- 제약
  - 서버의 일(올린 문서의 장 나누기·코멘트 → 확인 요청·참고문헌·수정본·출처 확인 문서, 인용 점검)은 컨텍스트와 상관없이 그대로 돌아야 한다.
    인용 게이트(원문을 확인한 문헌만 인용)는 컨텍스트 글이 아니라 데이터로 판단한다.
  - 도구 29개·도구 목록 10,900토큰이 늘면 안 된다. MCP 도구 이름은 바꾸지 않는다(CLAUDE.md).
  - 이전은 시험 공간 사본에서만. 서버 데이터는 층 이전 전(#93 전)이므로 층 이전 전·뒤 어느 쪽에서 시작해도 같은 결과여야 한다.
  - 실사용자 공간 불변, 서버 접속 없음, 외부 라이브러리 없음(#56).

## Action

**저장**
- 글은 모두 책의 항목 파일(`shelf/categories/<책 id>/items/<글 id>.json`)이다. 생각(`shelf/casper`)·문체(`shelf/balthasar`) 파일은 이전 때 항목으로 옮기고
  (작성자·응답한 글(parent_id)·origin·kind·제목·tags_by를 그대로, 문체의 work → 위치, tags → "호흡: 짧음" 같은 태그), 그 폴더는 더 쓰지 않는다.
- 문헌은 `shelf/melchior/<key>/`에 그대로 둔다(key 하나·aliases·발췌·전문·인용 게이트). bib.json에 `"book"`(그 문헌이 든 책 id)을 더해,
  화면과 도구에서는 그 책의 '문헌 글'로 보인다. 글에 서지(source)가 있으면 문헌 글이고, 원문을 확인했으면(checked) '원문 확인' 표시가 붙는다.
- 컨텍스트는 붙인 곳의 파일에 **사본**으로 적는다: `category.json`·`project.json`(올린 원고)·`document.json`(원고에서 만든 문서)·지도 파일의 노드에
  `"contexts": [{"name", "text"}]`. 자주 쓰는 컨텍스트는 `shelf/contexts.json`(사람마다). 파일이 없으면 처음 제공하는 넷이고, 처음 고칠 때 파일에 적는다.
- 색인 v20: ideas·style_entries 테이블을 뺐고, category_items에 이유·위치·쓸 부분·parent_id·origin·kind·tags_by, refs에 book, 책·원고·문서에 contexts.

**컨텍스트 규칙**
- 노드와 책에 붙인다. 책에 하나라도 있으면 책의 것만, 없으면 그 책이 꽂힌 노드의 것을 따른다. 여럿이면 붙인 순서대로 잇는다.
- 이름 20자, 내용 500자, 한 곳에 4개, 자주 쓰는 것 20개까지. 연결 노드는 원본 노드의 것을 쓴다(연결 노드에서는 못 바꿈).
- AI에게는 노드·책을 읽거나 넣는 도구의 응답 머리에 전문을 싣는다: `컨텍스트(책 「문체」): 「문체」 문학적 부분이 …`
  (노드의 것을 따르면 `컨텍스트(책 「X」, 노드 「Y」의 것)`, 없으면 `컨텍스트: 없음(일반 메모로 다룬다)`). JSON 응답(book_read_chapter·ref_check)은 `"context"` 칸을 맨 앞에.
  전체 현황(book_outline)과 지도 보기(category_list)는 이름(이름이 없으면 첫 줄 앞부분)만.
- 서버는 컨텍스트 글을 읽어 판단하지 않는다. 인용 점검은 '원문 확인' 표시와 참고문헌 항목만 본다(범위는 #95 그대로: 그 프로젝트 + 연결 노드가 가리키는 책).
- 원고를 올리면 「원고」, 출처 확인 문서를 만들면 「출처 확인 문서」 컨텍스트를 붙인다. 참고문헌을 받을 책이 없으면 「참고문헌」 책을 만들고 「논문」을 붙인다.

**도구(29 → 23개, 10,900 → 8,416토큰)**
- 글 넣기 = `category_put`(이름 그대로): book, author, content, title·title_by·untitled, 이유(reason), 위치(where), 쓸 부분(parts),
  서지(source)·원문 확인(checked)·파일(file)·aliases, 칸·태그·장, item_id(고치기). idea_add·style_add·ref_add를 대신한다.
- 찾기 = `category_search`(book·project·author·full): idea_search·style_search·ref_search를 대신한다. 결과는 책으로 묶고 책마다 컨텍스트 머리.
- 지우기는 이미 `category_trash` 하나(#94). 자주 쓰는 컨텍스트 보기는 `category_list`, 붙이기는 `category_create`·`category_edit`의 context(이름이나 글).
  자주 쓰는 컨텍스트를 만들고 고치는 것은 웹에서만.
- 남긴 것: idea_add_conversation(넣을 책 book), ref_import_bibliography(책 book), ref_check, 올린 문서 도구(book_*), files_list, category_title_default.
- 인자 이름 category → book(용어집 '책(도구의 book)').
- 넣을 곳을 말하지 않으면: 대화에서 다루는 노드·책이 분명하면 그 책, 아니면 책 이름과 컨텍스트 이름을 보여 주며 묻는다(규칙 8).

**웹**
- 노드 만들기('+ 노드', 작은 칩)·책 만들기·책 설정·노드 설정에 컨텍스트 칸: 자주 쓰는 것을 누르면 붙고 다시 누르면 떨어지며, 붙인 사본은 그 자리에서 고친다.
  줄마다 '자주 쓰는 컨텍스트로 등록'. 직접 적기는 접힌 칸.
- 노드 패널·책 게시판·올린 원고·문서 머리에 컨텍스트 이름(누르면 전문). 책등 위 띠 = 컨텍스트 이름(첫 이름 + "외 N"), 없으면 비움.
- 내 정보 아래 '자주 쓰는 컨텍스트'(`/me/contexts`: 고치기·지우기·새로 더하기).
- 종류 이름을 뺐다: '원고 책' → '올린 원고', '문서 책' → '원고에서 만든 문서', '모음 책 만들기' → '새 책', 책 추가 = 새 책 / 문서 올리기 / 원고에서 만든 문서.
  글 게시판은 하나(글 뒤에 문헌 글, 거르기: 나·AI·원문 확인).

**이전**(`magus maps plan|apply --backup|revert`, #95와 한 번에)
- 옛 기본 책 → 이름이 같은 책(생각·문체·문헌) + 컨텍스트(「생각 메모」·「문체」·「논문」), 원고 → 「원고」, 문서 책 → 「출처 확인 문서」,
  저자의 카테고리 → 컨텍스트 없는 책(칸 그대로). 휴지통의 생각·문체 → 그 책의 휴지통 글.
- 책 id는 정해진 값(`ideas-<프로젝트>`·`styles-common`·`refs-<프로젝트>`, `"legacy"` 표시), 만든 시각은 그 책의 첫 글 시각 → 두 경로 결과가 같다.
- revert: 글을 생각·문체 파일로 되돌리고, 문헌의 book을 떼고, 이전으로 생긴 책은 `categories.reverted-<시각>`로 비켜 둔다(지우지 않음).
- 서버(`magus serve`)는 옛 형식 책장이 남은 사용자가 있으면 시작하지 않는다(이전을 빠뜨린 배포를 막음).
