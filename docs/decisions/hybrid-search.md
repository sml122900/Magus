# 하이브리드 검색: 한글 bigram FTS5 + 벡터 RRF, 임베딩은 파생값이고 실패하면 FTS로

- 날짜: 2026-10-03 (야간 자율 작업)
- 단계: 4단계(FTS 토큰화 결정) + 7단계(벡터, 제공자, RRF 정리)
- 코드: `src/magus/textindex.py`, `src/magus/search.py`, `src/magus/embeddings.py`, `src/magus/store/shelf.py`(chunks), `tests/test_search.py`

## Problem

- 세 책장(발췌·전문, 생각, 문체)을 같은 방식으로 찾아야 한다.
- 원고는 한국어이고 고유명사가 짧다("갤러", "헨릭"). 조사가 붙는다("갤러는", "헨릭의"). SQLite FTS5의 기본 토큰화로는 조사가 붙은 어절이 통째로 한 토큰이 되고, trigram은 3글자 미만을 못 찾는다.
- 제약
  - 서버는 LLM API 키 없이 돌아야 한다. 외부 API는 임베딩뿐이고, `EMBEDDINGS=none`에서도 모든 도구가 동작해야 한다.
  - 인덱스는 파일에서 다시 만들 수 있어야 한다.
  - 오늘 밤은 실제 API를 호출하지 않는다.

## Action

- **FTS 토큰화**: 한글·한자·가나 연속열은 2글자씩 겹쳐 자른 bigram(갤러는 → 갤러, 러는)으로, 라틴 문자와 숫자는 소문자 단어로 미리 토큰화한다. 그 결과를 FTS5(unicode61)의 `tokens` 열에 넣는다. 질의도 같은 방식으로 쪼개 `"갤러" OR "러는"`처럼 묶고, bm25로 순위를 매긴다.
- **벡터**: 청크마다 float32 BLOB을 저장하고, 질의 때 numpy로 코사인을 한 번에 계산한다(브루트포스). P0 규모(수만 청크)면 충분하다.
- **결합**: RRF(k=60)를 쓴다. 두 목록의 순위만 쓰므로 bm25와 코사인의 척도를 맞출 필요가 없다. 두 목록에 다 나온 청크가 위로 온다.
- **임베딩은 파생값이다**: 파일에 저장하지 않는다. 인덱스를 다시 만들면 비고, 검색할 때 `embed_missing`이 빈 청크를 배치로 채운다. 새로 쓴 글도 같은 경로로 채워진다.
- **실패해도 계속한다**
  - 제공자가 없으면(none, 또는 키 없음) FTS만 쓴다.
  - API 호출이 실패하면 경고 로그를 남기고 FTS 결과로 계속한다. 도구가 오류를 내지 않는다.
- **제공자 스텁**
  - Voyage(기본 voyage-3.5)와 OpenAI(text-embedding-3-small)를 표준 라이브러리 HTTP로 부른다(SDK 의존성 없음).
  - `post` 함수를 주입할 수 있어서, 테스트는 네트워크 없이 요청 모양(URL, 헤더, payload, 응답 index 정렬)만 확인한다.
- **레인**: ref_picked, ref_full, idea_me, idea_ai, style. 레인별 순서 규칙은 호출하는 쪽이 정한다(발췌 먼저, me 먼저). 문체 레인의 청크는 reason + tags다.
- 비교한 대안
  - **trigram 토크나이저**: 2글자 이름을 못 찾는다.
  - **형태소 분석기(kiwi, mecab)**: 설치가 무겁고, 학자 이름 같은 미등록어를 오히려 쪼갠다.
  - **sqlite-vec 같은 확장**: Windows 배포가 번거롭고, P0 규모에는 브루트포스로 충분하다.
  - **점수 가중합**: 척도를 맞추는 튜닝이 필요하다.

## Result

- `tests/test_search.py`
  - "해양"으로 찾으면 FTS만으로는 0건이고, 가짜 임베더(개념 사전)를 붙이면 "바다는…"이 1위로 나온다.
  - 키워드와 벡터에 모두 걸리는 청크가 1위다.
  - reindex 뒤에는 임베딩이 비었다가 다음 검색 때 다시 채워진다.
  - 임베더가 예외를 내도 FTS 결과가 그대로 나온다.
  - Voyage/OpenAI 요청 모양을 네트워크 없이 확인했다.
- 2글자 이름 검색(`ref_search "고래"`), 조사가 붙은 어절 검색을 테스트로 고정했다.
- 완료 기준 "EMBEDDINGS=none에서 모든 도구가 동작"을 확인했다. 하위 프로세스 stdio 테스트가 EMBEDDINGS=none으로 18개 도구를 모두 한 번씩 부른다.

> 대안을 버린 이유: trigram은 짧은 이름을, 형태소 분석기는 미등록 학자 이름을 놓치고, 벡터 확장과 가중합은 P0에 비해 무겁다. 그래서 의존성 없는 bigram FTS와 순위만 쓰는 RRF로 정했다.
