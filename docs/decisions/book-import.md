# book_import: docx XML 직접 파싱, 목차 판별, 재실행 안전성

- 날짜: 2026-10-03 (야간 자율 작업)
- 단계: 2단계
- 코드: `src/magus/book/{docx_reader,pdf_reader,importer,comments}.py`, `src/magus/melchior/bibliography.py`, `src/magus/synthetic.py`, `tests/test_import.py`, `tests/test_bibliography.py`

## Problem

- 실제 사례의 원고는 34만 자, 35장 8부, Word 코멘트 86개, 참고문헌 약 250편이었다. 이것을 장 단위 파일과 미해결·refs로 옮겨야 한다.
- 코멘트의 **앵커**(어느 글에 달렸는지)가 핵심이다. "확인 필요"만 적힌 코멘트가 대부분이라 앵커가 없으면 무엇을 확인하라는지 알 수 없다. 코멘트 범위는 문단과 표를 가로지를 수 있다.
- 원고 앞에는 보통 목차가 있다. 목차에도 "제1장 …"이 그대로 나오므로, 같은 장 제목이 두 번 나온다.
- 제약: 실제 원고가 아직 없다(합성 fixture로 개발). 아침에 실파일로 다시 돌릴 수 있어야 하고, 다시 돌려도 사람이 고친 것이 사라지면 안 된다.

## Action

- **docx는 zip 안의 XML을 직접 읽는다**(`lxml`).
  - python-docx의 문단 API는 코멘트 범위(`commentRangeStart/End`), 내용 컨트롤(`sdt`, 목차가 흔히 여기 들어감), 변경 추적의 삭제분(`w:del`), 필드 코드(`instrText`)를 다루지 못한다. mammoth는 HTML로 바꾸는 과정에서 코멘트 위치를 잃는다.
  - 문서 순서대로 걸으며 열린 코멘트마다 앵커 글을 모은다. 범위 없이 한 점에만 달린 코멘트는 그 문단 전체를 앵커로 쓴다.
  - 그림(`drawing/pict/object`)은 `[그림 N]`, 수식(`m:oMath`)은 `[수식]`, 표는 `[표 N]`로 바꾼다. 표 안에 걸린 코멘트의 앵커도 모은다.
- **제목 판별**
  - `제\s*N\s*부`·`제\s*N\s*장` 뒤에 구분자(공백·콜론·대시) 또는 줄 끝이 와야 하고, 80자 이하여야 한다. 그래서 "제1장에서 보았듯이…"는 제목이 아니다.
  - 제목이 비어 있으면 다음 줄(60자 이하, 문장 끝이 아닌 것)을 제목으로 쓴다.
  - 목차의 쪽번호 꼬리(`\t3`, `....3`)는 지운다.
- **목차 판별**
  - 같은 장 번호가 여러 번 나오면 뒤따르는 본문이 가장 긴 것을 진짜 제목으로 본다.
  - 부 제목은 바로 다음 제목이 진짜 장 제목일 때만 인정한다.
  - 버린 제목 줄은 리포트에 "목차 등으로 판단해 버린 제목 줄"로 남긴다.
- **장 밖의 글**: 첫 진짜 제목 앞(표지·목차·머리말)과 부 제목 아래의 글은 장으로 만들지 않는다. 이 글은 `original/unsplit.md`에 보관하고 리포트에 "분할 못 한 구간"으로 남긴다(머리말을 ch-00으로 만들지는 검토 대기).
- **코멘트 → 미해결**
  - 본문은 `코멘트 + "— 원문: “앵커 120자”"`로 만든다.
  - 장은 앵커 블록이 속한 구간으로 정한다. 참고문헌이나 장 밖 구간이면 장을 비워 두고 리포트에서 따로 센다.
  - `classify_comment(코멘트, 앵커)`로 kind와 ref_key를 붙인다.
- **참고문헌**
  - 마지막 "참고문헌" 제목 아래 문단 하나를 문헌 하나로 본다.
  - 파싱하지 못한 줄도 `raw-<해시>` key로 보관한다(유실 방지).
  - 같은 목록 안에서 key가 겹치면 `-2`를 붙인다. APA 연도 접미사(2012a)가 있으면 그대로 key에 넣는다.
- **재실행 안전성**
  - 원본은 무엇보다 먼저 `original/`에 복사한다.
  - 같은 project_id가 있으면 기본적으로 거부한다. `replace=True`일 때만 기존 프로젝트 폴더를 `users/<id>/trash/<id>-<시각>/`로 옮긴다(삭제하지 않음). 사람이 고친 본문과 versions/가 그대로 남는다.
  - refs는 사람 소유 책장이므로, 다시 임포트할 때 이미 있는 key는 건드리지 않는다(verified 승격을 덮어쓰지 않으려는 것).
- **PDF 폴백**: pymupdf 블록 단위로 읽는다. `메모 포함[C n]: …` 블록을 코멘트로 떼어 내고, 바로 앞 블록을 앵커로 본다. 리포트에 "코멘트는 PDF 텍스트에서 추출"이라고 표시한다.
- **합성 fixture**(`magus synth`)
  - 원고: 목차, 공백 변형 제목, 다음 줄 제목, 두 문단에 걸친 코멘트, 표·그림·수식, 참고문헌 30줄(실패 3줄, 충돌 1건, 국역 꼬리 8건).
  - PDF: 말풍선을 흉내 낸 합성 PDF.
- 비교한 대안
  - **python-docx 문단 API**: 코멘트 범위와 sdt를 놓친다.
  - **mammoth → HTML**: 코멘트 위치를 잃는다.
  - **pandoc docx → md**: 코멘트를 span으로 보존하지만, 앵커가 여러 문단에 걸칠 때 다루기 어렵고 자리표시자 번호를 맞추기 어렵다.

## Result

- 합성 원고 기준(`tests/test_import.py`, `data/synthetic-fixtures/step2-import-report.md`)
  - 장 7개, 부 3개를 찾았다. 목차 줄 11개를 정확히 버렸다. 빠진 번호와 본문 없는 장은 없다.
  - 코멘트 13개가 이슈 13건이 됐다: citation 8, general 5. ref_key 후보는 citation 8건 중 6건(75%)에서 찾았다. 장 밖 코멘트는 머리말 1건, 참고문헌 1건이다.
  - 참고문헌 30줄 → refs 30건(unverified). 파싱 실패 3줄은 raw로 보관했고, key 충돌 1건(hu2023 → hu2023-2)이 있었다.
  - 국역 aliases가 들어갔다(갤러2022, 갤러2023 → galor2022 / 헨릭2016 → henrich2016).
  - 재실행을 확인했다. 같은 id는 거부되고, 새 id로 다시 임포트하면 refs는 기존 30건을 그대로 쓴다. replace=True면 기존 프로젝트가 휴지통으로 가고, 사람이 고친 본문과 versions/가 그곳에 남는다.
  - reindex 전후로 장·이슈·refs가 같다.
- 알려진 한계(4단계 과제): "일어서지"의 "서지" 오탐(I6), 조사가 붙은 한글 저자 key(`갤러는2022`, I4).
- 실원고의 완료 기준(35±2장, 8부, 코멘트 80건 이상, refs 200건 이상)은 fixtures가 들어오면 확인한다.

> 대안을 버린 이유: 고수준 변환기(python-docx 문단 API, mammoth, pandoc)는 모두 코멘트 앵커나 목차 구조를 잃는다. 이 기능의 핵심이 "어느 글에 달린 확인 요청인가"이므로 XML을 직접 걷는다.
