## Problem

- 화면마다 설명 문단·안내 문장이 길게 붙어 있었다(예: 원문 확인 넣기 폼 위 5줄, 지도 아래 4줄, 노드 설정의 휴지통 문단). 주 사용자(고령의 저자)에게는 읽을 것이 많아 오히려 단추가 묻혔다.
- 게시판의 글 쓰기·보기에 이유·위치·칸·쓸 부분·태그 같은 칸이 섞여 '게시판'보다 '양식'에 가까웠고, 원문 확인은 거르기 링크와 별도 입력 폼(쓸 부분·이유·쪽수)으로 따로 놀았다.
- 글에 사진·원문 파일을 붙일 수 없었다.
- instructions 규칙 12가 book_document 전에 점검 도구 셋(book_questions·ref_check·book_issues)을 먼저 부르게 해, 서버가 데이터로 만드는 문서인데도 도구 호출이 늘었다.
- 제약: 데이터는 지우지 않는다(원문 확인 표시·기존 칸은 저장 형식 그대로, 인용 점검도 그대로). 배포 전후 수치 같음(father 문헌 337·미확인 335·확인 요청 129·수정본 3, default 297·86).
  API 키는 서버에만, API로는 질문·도움말 문서·화면 이름만, 로그에 질문·답·메일 없음. 실제 사용자 공간(default·father)은 건드리지 않는다.

## Action

**A. 화면 글자 최소화**
- 남기는 것: 제목, 단추 이름(동사 하나: 저장·만들기·올리기·취소·옮기기·휴지통…), 입력칸 이름, 날짜, 개수. 그리고 결과 한 줄(오류·완료, 짧게)과 조작 중 상태(지도의 live region).
- 아이콘만으로 뜻이 분명한 곳은 아이콘 + aria-label·title: ⚙(책 설정·노드 설정), 🔗(글 주소), ?(도움말), ✕(닫기).
- 빈 화면은 한 줄 + 단추 하나(빈 책 "글이 없습니다." + '새 글', 올린 파일 "파일이 없습니다." + '올리기').
- 컨텍스트가 없을 때의 '없음 — …' 문구는 지웠다(아무것도 보이지 않음). 노드 → 책 읽는 순서 설명은 도움말로.
- 책 추가의 '올린 문서에서 만든 문서' 카드는 설명뿐이라 뺐다(대화로 만든다, 도움말에 예문).
- 올린 파일 화면의 '쓰임' 열은 도구 이름이 보이던 곳이라 뺐다.
- 걷은 문장은 `docs/help/`로 옮겼다: 01 용어 사전(사용자가 정한 이름 그대로) · 02 화면별 설명 · 03 자주 하는 일 · 04 한도와 규칙 · 05 Claude 대화로 하는 일.
  옮긴 문장 목록은 `private/tmp/removed_texts.txt`(diff에서 뽑음, 336줄).

**B. 게시판 = 제목 + 글 + 첨부**
- 새 글·고치기 폼은 제목·본문·첨부(여러 개)뿐. 칸(인물·사례 등)·이유·위치·쓸 부분·태그·연결된 장·출처·응답 관계·고친 사람은 파일에 그대로 두고 보이지 않는다
  (웹에서 고쳐도 `replace`로 그 칸을 보존한다. 시험으로 고정). 'AI'·'AI 제목' 표시는 남겼다(누가 말했는지 보존 원칙).
- 칸 값만 있는 글이 비어 보이지 않게, 칸은 본문 아래 "칸: 값" 줄로 보인다(입력은 대화로).
- 원문 확인 거르기(🟢/🟡)와 원문 확인 넣기 폼(`/shelf/refs/register`)을 없앴다. 문헌 글을 펼치면 '원문 확인' 체크 하나(누르면 바로 저장, 스크립트가 꺼지면 '저장' 단추).
  체크는 `bib.json`의 `status`만 바꾸고 `status_by`(누가·언제·web)를 남긴다. 쓸 부분·서지·전문은 그대로이고, 인용 점검 수는 그 자리에서 다시 센다.
- 첨부: `shelf/categories/<책>/files/<글>/<첨부 id>/<이름>`(문헌 글은 `shelf/melchior/<key>/files/…`). 사용자 폴더 안이라 restic 백업에 그대로 들어간다.
  경로는 서버가 만든 id 폴더라 이름으로 다른 곳을 가리킬 수 없다(이름은 폴더 이름을 떼고, 구분자·특수 문자·숨김·예약 이름 거부).
  한 개 `MAX_ATTACH_MB`(기본 20), 한 번에 10개, 사용자 전체 `MAX_USER_MB`. 형식은 문서·표·발표·그림(SVG·HTML·실행 파일 없음).
  보기는 세션 사용자의 폴더에서만 찾고, 그림·PDF만 inline(nosniff, 그림은 CSP), 나머지는 내려받기. 글·책 휴지통에 첨부도 함께, 첨부 하나를 빼면 `trash/shelf/attachments/`로.
- MCP: category_search 결과의 글·문헌 글에 `첨부 N개: 이름(종류, 크기)`만. 첨부 내용을 읽는 도구는 이번 범위가 아니다.
- **데이터 구조**: 기존 파일 형식은 바꾸지 않았다(새 폴더 `files/`, bib.json에 선택 키 `status_by`만). 그래서 이전(plan → apply → revert)이 필요 없다.
  시험 공간 사본(default·father-trial 복사)에서 옛 코드(9f8e01e)와 새 코드의 전체 현황이 글자까지 같고(로그 줄 제외), 새 코드가 원본 파일을 하나도 바꾸지 않았으며,
  첨부·체크가 든 데이터를 옛 코드가 그대로 읽는 것(되돌리기 안전)을 확인했다(`private/tmp/razor_numbers.sh`).

  사용자 메시지 = "지금 화면: <정해 둔 화면 이름>\n\n질문: …". 화면 이름은 서버가 주소로 정한 열쇠(SCREENS)만 받아 이름으로 바꾼다(브라우저가 보낸 임의 문자열은 '기타').
