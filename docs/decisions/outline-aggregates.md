# outline은 집계만: 코멘트 유래 미해결은 건수로, 목록은 book_issues로

- 날짜: 2026-10-03
- 단계: 1단계 확정(검토 대기 결정 답변 + 보완)
- 코드: `src/magus/book/outline.py`, `src/magus/book/tools.py`(`book_issues`), `tests/test_outline.py`, `tests/test_server.py`

## Problem

- 1단계 outline은 열린 미해결을 모두 같은 줄 형식으로 실었다. 실제 원고처럼 코멘트가 86건이면 목차가 예산을 먼저 쓰고, 미해결은 86건 중 7건만 실린 채 "외 79건"으로 접혔다(추정 2,846/3,000토큰).
- 그런데 접혀서 안 보인 것이 사람이 직접 남긴 미해결일 수도 있었다. Word 코멘트 86건 중 82건은 "확인 필요"류였다. 소수의 중요한 미해결이 대량의 기계적 코멘트에 묻히는 구조였다.
- 제약: 예산 3,000토큰은 유지한다. 책 전체나 긴 목록을 돌려주는 도구는 만들지 않는다.

## Action

- **목차 줄은 집계만 싣는다**: `제N장 제목 · 상태 · N자 · 미해결 n · 미확인인용 n`. 장별 미해결 수에는 코멘트 유래까지 센다. 장 제목은 24자에서 자른다.
- **미해결 전문은 출처로 거른다**: `user`·`agent`가 남긴 것만 전문을 싣는다(80자 → 60자로 자름). `import_comment`는 `코멘트 유래 미해결 N건 — book_issues로 조회` 한 줄로 줄였다.
- **예산 배분 순서를 바꿨다**: 머리 → 목차 → 직접 남긴 미해결 → 결정 → 변경. 전에는 미해결이 맨 마지막이었다.
- **목록은 새 도구로 뺐다**: `book_issues(status, chapter_number?, origin?, kind?, limit=50)`. 조회 전용이고, 한 줄에 한 건을 싣는다. limit은 최대 200이고, 넘치면 "앞 N건만 표시"라고 알린다.
- 같은 시점에 2단계 준비로 이슈에 `kind`(citation|general)와 `ref_key` 후보를 더했다. book_issues에서 `kind=citation`으로 출처 확인 코멘트만 뽑아 볼 수 있다.
- 비교한 대안
  - **미해결을 장별 건수로만 표시**: 사람이 남긴 중요한 미해결까지 숨는다.
  - **예산을 늘리기**: "에이전트는 책 전체를 들고 있지 않는다"는 원칙과 충돌하고, 문제를 미룰 뿐이다.
  - **book_read_chapter의 open_issues로만 조회**: 장에 속하지 않은 미해결이나 citation만 모아 보는 질의를 할 수 없다.

## Result

- `test_outline_fits_budget_and_lists_every_direct_issue`: 일부러 불리하게 잡은 가짜 책에서 측정했다(35장·8부, 장 제목 28자, 장당 9,700자, 코멘트 유래 86건, 결정 15건, 사용자 12건 + 에이전트 4건).
  - 추정 2,893/3,000토큰이다.
  - **직접 남긴 미해결 16건이 전부 실린다.**
  - 코멘트 유래는 한 줄이고, 코멘트 본문은 outline에 나오지 않는다.
  - 가장 최근 결정과 변경은 반드시 실린다. 이 규모에서는 결정 10건 중 7건, 변경 5건 중 2건이 실리고 나머지는 "외 N건"으로 접힌다.
- `test_book_issues_lists_and_filters`: status·origin·chapter·kind 필터와 limit 알림을 확인했다. 잘못된 origin 값은 스키마에서 거부된다.
- 실제 원고(2단계)로 다시 잴 예정이다. 실제 장 제목은 이 가짜보다 짧을 가능성이 크다.

> 대안을 버린 이유: 건수만 보이면 사람이 남긴 미해결이 묻히고, 예산을 늘리면 원칙과 충돌한다. 그래서 출처로 걸러 사람의 미해결만 전문을 싣고, 나머지는 조회 도구로 뺐다.
