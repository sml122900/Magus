# 웹 수정 묶음: 글 고치기 복원·제목 자동 채움·스크랩·찾기 보강·첨부 고르기·책 색·책등·정해진 이름 안내(2026-10-09, 사용자 요청 #99)

## Problem
- 지난 블록(#98)에서 웹의 글 고치기를 없앴더니 저자가 고칠 길이 없어 불편했다. 첨부 하나만 빼거나 더하는 길도 함께 없어졌다(#98-f).
- 첨부만 붙인 글은 제목이 없어 게시판에서 본문 앞부분(또는 '파일.확장자')이 흐리게 보였다.
- 중요한 글을 표시해 두고 모아 볼 방법이 없었다.
- 「raw-3fb7a700()」가 `raw`로는 찾아지고 `ra`로는 안 찾아졌다. 색인이 낱말(라틴)·2글자 조각(한글) 단위라 앞부분·중간 글자로는 못 찾았고,
  웹 찾기와 대화의 category_search가 서로 다른 길을 썼다. 첨부 파일 이름은 색인에 없었다.
- '파일 고르기'를 다시 누르면 앞서 담은 파일이 사라졌다(input.files를 덮어씀). 담은 파일을 뺄 방법도 없었다.
- 책 설정의 기본 색 격자 18칸이 색 선택기를 아래로 밀었다. 세로 책등에서 숫자·영문만 누워 "수정본2"가 읽기 어려웠다.
- "'수정본'은 정해진 이름이라 …"만으로는 왜 안 되는지, 무엇을 하면 되는지 알 수 없었다.
- 제약: 데이터는 지우지 않는다. 저장 형식은 표시 하나 더하는 정도로만 바꾸고 옛 코드가 읽어도 깨지지 않게. 도구 수 23개 유지.

## Action
- **글 고치기 되돌림**: 글 보기 '✎ 고치기'(🗑 옆, 같은 크기) → 글쓰기와 같은 폼(채워진 채). `Store.patch_category_item`이 바꾼 칸(제목·본문·고친 시각)만
  파일에서 고치고 나머지(누가·이유·위치·쓸 부분·태그·칸·응답 관계·모르는 칸)는 바이트까지 그대로 둔다. 문헌 글은 `set_ref_memo`(메모만, status_by 그대로).
  기존 첨부마다 ✕ → 지우지 않고 휴지통(새 휴지통 종류 `attachment`), 프로젝트 휴지통에서 그 글로 되살린다. 원칙: 웹에서 없애는 것은 모두 휴지통을 거친다.
- **제목 자동 채움**: 웹 쓰기·고치기에서 제목이 비고 첨부가 있으면 첫 첨부의 파일 이름(확장자 제외)을 제목으로 저장(title_by=author).
  이미 저장된 글은 파일을 바꾸지 않고 보일 때만(`attachments.shown_title`). 대화(category_put)는 제목 규칙 그대로.
- **스크랩**: 글 파일·bib.json에 `"scrap": true` 하나(끄면 키를 뺀다, 고친 시각 그대로). 색인 칸 `scrap`. 웹 ☆(fetch, 44px, aria-pressed)·'★ 스크랩만'(?scrap=1, 개수).
  MCP는 도구를 늘리지 않고 `category_search(scrap_only)`·`category_edit(scrap, item_id)`, 결과에 ★. instructions 6·7에 한 줄씩.
- **찾기 보강**: `search.find_chunks` 하나를 웹과 대화가 함께 쓴다. 1단계 FTS(라틴·숫자·한 글자는 앞부분 일치 `"ra"*`, 한글 2글자 조각, 따옴표 구절,
  토큰만 큰따옴표로 묶어 FTS 문법 오류 없음, 낱말 하나면 가장 가까운 낱말부터) → 2단계 글자 그대로 포함(대소문자 무시, 최근 글부터, 같은 글은 한 번).
  첨부 파일 이름을 색인에 넣고(첨부가 바뀌면 그 글만 다시 색인), 색인 v22로 배포 뒤 첫 시작 때 모두 다시 만든다(내용 파일은 그대로).
- **첨부 고르기**: 담은 파일을 스크립트 배열로 들고, 고르기·끌어다 놓기 모두 더하기, 파일마다 ✕, 10개 초과·크기·형식은 담는 순간 그 파일만 빼고 안내, 보낼 때 FormData를 목록에서.
- **책 색**: 색 선택기 먼저, 기본 색은 '기본 색 ▾'(접힌 details). 스크립트 없이 색 선택기만 바꿔도 저장되게 처음 색(was)과 견준다.
- **책등**: `text-orientation: upright`, 2~4자 숫자·영문은 `text-combine-upright: all`, 5자 이상 영문은 눕힘(세움과 둘 다 캡처해 고름).
- **정해진 이름 안내**: 규칙 그대로, 문구에 이유·다음 행동·`RESERVED_SHOWN`(저자에게 보이는 이름만) 목록. 옛 이름·코어 이름(`RESERVED_HIDDEN`)은 막기만.
- 비교한 대안
  - 고치기를 파일 전체 다시 쓰기(put_category_item)로: 이 코드가 모르는 칸·빈 쓸 부분 같은 것이 떨어질 수 있다. 바꾼 칸만 고치는 쪽이 숨긴 칸 보존을 보장한다.
  - 스크랩을 별도 파일(scraps.json)로: 휴지통 왕복·내려받기·되돌리기 때 따로 챙겨야 한다. 글 파일의 표시 하나면 글을 따라다닌다.
  - 찾기를 trigram 토크나이저로: 2글자 한국어 이름("갤러")을 못 찾고 색인이 커진다. 앞부분 일치 + 글자 포함 뒤붙임이 기존 색인을 그대로 쓴다.
  - 스크랩 도구 새로 만들기: 도구 수·설명이 늘고 커넥터가 길어진다. 기존 찾기·고치기 도구에 인자 하나씩.
