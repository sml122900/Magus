# 웹 화면 스타일 (2026-10-06)

## Problem

- 웹 화면(`/book`·`/inbox`·`/issues`·`/checklist`, 세 책장 `/ideas`·`/refs`·`/styles`)은 브라우저 기본 모양이었다. 주 사용자는 고령의 저자(아버지)라 글이 작고, 버튼과 입력칸이 잘 보이지 않았다.
- 제약
  - 결정 #56: 템플릿 엔진·외부 글꼴·CDN 없이 서버에서 그린 HTML. 스타일은 `web.py`의 `STYLE` 상수 한 곳에 둔다.
  - 화면 문구는 바꾸지 않는다(문구 변경은 사용자 결정으로만. 용어 통일 #85가 그 예다).
  - 휴대폰(폭 390px)에서도 읽히고 눌려야 한다.
- 출발점: 외부 디자인 분석 문서(private/design)의 색·모서리·간격 토큰. 이 문서는 홍보 페이지용이라 그대로 쓰면 작업 화면에서 읽기 어렵다(가는 글씨, 15px 본문, 그라데이션 배경).

## Action

**선택: 참고 문서의 색·모서리·간격 토큰만 가져오고, 글꼴·굵기·크기·대비는 가독성 기준으로 다시 정했다.**

### 실제로 쓰는 토큰

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--ink` | #0d253d | 본문 글자, 제목 |
| `--ink2` | #273951 | 메뉴, `small`, 쪽 이동, 접힌 영역 제목 |
| `--mute` | #64748d | 표 머리, 표 안 작은 글, 사용자 이름, 비활성 선택지, **입력칸 테두리**. 흰 바탕에서만 쓴다 |
| `--primary` | #533afd | 링크, 채운 버튼, 지금 보고 있는 메뉴 밑줄, 키보드 선택 테두리 |
| `--deep` | #4434d4 | 채운 버튼에 마우스를 올렸을 때, 알약 태그 글자 |
| `--press` | #2e2b8c | 링크에 마우스를 올렸을 때, 채운 버튼을 눌렀을 때 |
| `--canvas` | #ffffff | 상단 바, 카드, 표 상자 |
| `--soft` | #f6f9fc | 페이지 바탕 |
| `--line` | #e3e8ee | 구분선, 카드 테두리 |
| `--ruby` | #ea2261 | 오류 메시지 왼쪽 띠(글자에는 쓰지 않는다) |
| `--tag` | rgb(185 185 249 / 40%) | 알약 태그 바탕(흰 바탕 위에서 #e3e3fd) |
| `--shadow` | rgba(0,55,112,.08) 0 1px 3px | 카드·표 상자 그림자 하나 |

- **글꼴 스택**: `-apple-system, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", system-ui, sans-serif`. 줄바꿈은 `word-break: keep-all`(어절 단위).
- **굵기**: 본문 400, 제목·상단 이름·표 머리 600. 300은 쓰지 않는다.
- **크기**: 본문 16px, 줄간격 1.6. 제목 26/20/18px(휴대폰 h1은 22px). 표 머리 13px. 버튼 글자 16px.
- **간격**: 참고 문서의 눈금(2·4·8·12·16·24·32px)만 쓴다. 본문 폭 최대 1100px, 바깥 여백 24/16/32px(휴대폰 16/12/24px). 카드 안 여백 16×24px, 표 칸 8×12px.
- **모서리**: 카드·표 상자·메시지 12px, 입력칸 6px, 버튼·태그 9999px(알약).
- **누르는 곳**: 버튼·입력칸 높이 40px 이상(휴대폰 44px). 키보드 선택은 3px `--primary` 테두리.
- **채운 버튼은 화면마다 하나**: 받은함·원고의 '올리기'. 나머지는 테두리 버튼이다(참고 문서의 "한 띠에 채운 알약 하나"를 따랐다).

### 참고 문서에서 바꾼 점과 이유

| 항목 | 참고 문서 | 우리 | 이유 |
|---|---|---|---|
| 글꼴 | 전용 라틴 글꼴 + 음수 자간 | 운영체제의 한글 글꼴 스택, 자간은 제목만 -0.2px | #56(외부 글꼴 없음). 한글 글자 모양이 있어야 하고, 음수 자간은 한글을 뭉개 보이게 한다 |
| 굵기 | 본문·제목 300(가는 글씨) | 본문 400, 제목 600 | 가는 한글 획은 고령 사용자에게 흐리게 보인다. 맑은 고딕에는 300이 없어 어차피 다른 굵기로 바뀐다 |
| 본문 크기 | 15px | 16px, 줄간격 1.6 | 가독성. 긴 표 칸과 확인 요청 본문을 오래 읽는다 |
| 그라데이션 메시 | 홍보 페이지 위쪽 배경 | 쓰지 않는다 | 작업 화면이라 장식이 필요 없고, 그라데이션 위 글자는 대비가 들쭉날쭉하다 |
| 입력칸 테두리 | hairline-input #a8c3de(흰 바탕 대비 1.82:1) | `--mute` #64748d(4.75:1) | WCAG 1.4.11(글이 아닌 요소 3:1)에 못 미쳐 칸이 어디 있는지 안 보인다. 사용자 결정 #86: 주 사용자 가독성이 디자인 충실도보다 먼저 |
| ink-mute 바탕 | 연회색 바탕에도 씀 | 흰 바탕에서만 | 연회색(#f6f9fc) 위 4.49:1로 AA(4.5:1)에 조금 모자란다 |
| ruby | 강조색 | 오류 메시지 왼쪽 띠만 | 흰 바탕 글자로 4.29:1이라 오류 글자색으로 쓰지 않는다 |
| 태그 바탕 | primary-bg-subdued-hover #b9b9f9 | 그 색을 40%로 | 그대로면 `--deep` 글자 대비가 낮다. 40%에서 6.20:1 |
| 어두운 대시보드 화면 | 있음 | 쓰지 않는다 | 화면이 적고 밝은 화면 하나로 충분하다 |
