# 사용자 서랍(drawer) — 설계안 초안, 미구현

- 날짜: 2026-10-06
- 상태: **검토 대기**(사용자 결정 #91). 구현하지 않았다.
- 요청: 저자가 이름을 붙인 카테고리("서랍")를 만들어 거기에 항목을 넣는다. 생각·문체·문헌 세 코어는 고정하고(이름 변경·삭제 불가, 인용 게이트와 문체 자문 동작 유지), 그 옆에 사용자 서랍을 더한다.
- 관련: [store-interface.md](store-interface.md)(파일이 원본, Store 뒤), [citation-gate.md](citation-gate.md), [instructions-from-registered-tools.md](instructions-from-registered-tools.md), [author-questions.md](author-questions.md)(#84), CLAUDE.md "저자에게 보이는 이름"(#85·#87·#90)

## Problem

- 원고에는 구조가 있는 재료가 많다: 인물(337편 문헌의 저자와 별개로 본문에 나오는 사람), 장소, 사례, 수치(사실·수치 확인 요청 82건), 용어, 연표.
- 지금은 넣을 곳이 생각(자유 메모)뿐이다. 그러면
  - 칸이 없다: "명태 어획량 1970년 몇 톤, 출처 해양수산부"를 한 줄 글로만 남긴다. 값·단위·기준 시점·출처를 따로 찾거나 고칠 수 없다.
  - 장과 이어지지 않는다(생각에는 장 필드가 없다. status.md "나중에 할 것").
  - 확인한 수치를 확인 요청(fact)과 잇는 기록이 없다. 확인 요청을 닫을 때 note에 손으로 적을 뿐이다.
- 제약
  - 원본은 사람이 읽을 수 있는 파일, SQLite는 인덱스(언제든 다시 만든다). 모든 행에 user_id.
  - 도구 이름은 접두어로 묶는다(`book_|ref_|idea_|style_|files_`). 응답은 짧게, 책 전체를 돌려주는 도구는 없다.
  - **누가 말했는지 보존한다.** 그리고 LLM 기억에서 나온 사실·수치가 원고에 들어가는 것이 이 서버가 막으려는 일(왜 만드나 3번)이다. 서랍은 그 통로가 되면 안 된다.
  - 저자에게는 용어집 이름만 보인다(#85·#87). 넣을 곳이 애매하면 묻는다(규칙 9, #90).

## Action — 설계

### 1. 세 코어와의 경계

| | 생각 | 문체 | 문헌 | 서랍(새로) |
|---|---|---|---|---|
| 무엇 | 떠오른 메모, 대화 발화 | 좋아서 모은 구절 | 읽고 등록한 책·논문 | 저자가 이름 붙인 칸 묶음(인물·수치 등) |
| 이름·삭제 | 고정 | 고정 | 고정 | 저자가 만들고 이름 붙임 |
| 특별한 동작 | me/ai 구분 | 문체 자문(style_search) | **인용 게이트**(verified만 인용) | 없음. 인용 게이트에 끼지 않는다 |

- 서랍 항목은 인용 근거가 되지 않는다. 수치 항목의 출처가 문헌 key면 그 문헌의 상태(🟢/🟡)를 보여 줄 뿐, 인용 판정은 언제나 문헌(refs)이 한다.
- 서랍은 **사람 소유**다(세 코어와 같다. 여러 책에 다시 쓴다). 책과의 관계는 항목의 장 연결(7절)로만 맺는다.

### 2. 저장 형태

```
data/users/<user_id>/drawers/<drawer_id>/drawer.json           # 서랍 정의
data/users/<user_id>/drawers/<drawer_id>/items/<item_id>.json  # 항목 하나
data/users/<user_id>/trash/drawers/<drawer_id>/items/<item_id>.json   # 휴지통(항목, "_trash" 덧붙임)
```

- `drawer_id`는 서버가 짓는 영문 id(`d-<시각>-<6자>`, 생각·문체 id와 같은 방식)다. 폴더는 id로, 이름은 drawer.json에만 둔다. 그래서 한글 이름을 자유롭게 쓰고, 이름을 바꿔도 파일을 옮기지 않는다.
- `drawer.json`
  ```json
  {"id": "d-20261007-a1b2c3", "name": "인물", "template": "인물", "created_at": "…",
   "fields": [{"key": "이름", "type": "text", "required": true, "title": true},
              {"key": "원어 표기", "type": "text"}, {"key": "생몰", "type": "text", "hint": "예: 1723–1790"},
              {"key": "설명", "type": "longtext"}, {"key": "관련 문헌", "type": "ref", "list": true},
              {"key": "메모", "type": "longtext", "retired": false}]}
  ```
  - 템플릿 칸은 만들 때 drawer.json에 **복사**한다. 코드의 템플릿이 나중에 바뀌어도 이미 만든 서랍은 그대로다.
- 항목 `items/<item_id>.json`
  ```json
  {"id": "20261007…-b1c2d3", "values": {"이름": "애덤 스미스", "생몰": "1723–1790"},
   "ai_fields": ["생몰"], "chapters": [{"project": "book", "number": 12}],
   "closes": ["I46"], "note": "", "created_at": "…", "updated_at": "…"}
  ```
  - `values`의 키는 그 서랍의 칸 이름만 받는다(모르는 칸은 거부).
  - **`ai_fields`: 저자가 말하지 않고 Claude가 채운 칸.** 누가 말했는지 보존한다(tags_by와 같은 생각, #89). 웹과 응답에 "AI가 채움"으로 보인다. 수치 서랍의 값·출처는 Claude가 기억으로 채우지 않는다(도구 설명에 적고, 수치 템플릿에서는 `값`·`출처`가 ai_fields에 들어가면 거부한다).
- 인덱스(SQLite, 모든 행에 user_id, 스키마 버전 +1)
  - `drawers(user_id, id, name, name_key, template, fields json, created_at, last_used_at)`: `name_key`는 6절의 정규화 이름이고, (user_id, name_key)는 유일하다.
  - `drawer_items(user_id, drawer_id, id, title, values json, ai_fields json, created_at, updated_at)`: `title`은 제목 칸 값이다.
  - `drawer_item_chapters(user_id, drawer_id, item_id, project_id, number)`: 장에서 항목을 찾는 쪽.
  - 검색: chunks에 새 레인 `drawer`(owner_type `drawer_item`, owner_id `<drawer_id>/<item_id>`)를 둔다. 색인 글은 서랍 이름 + 칸 이름: 값을 이은 것이다. FTS(한국어 bigram)와 임베딩은 지금과 같은 경로를 쓴다. lane CHECK에 `drawer`를 더한다.
  - `magus reindex`는 drawers/ 폴더에서 모두 다시 만든다. 파일에 없는 정보는 인덱스에 두지 않는다. 예외는 계산값(7절의 "언급된 장")이다.
- **Postgres(P2)와의 관계**: 표가 1:1로 옮겨 간다. `values`·`fields`는 jsonb(GIN 색인)로 간다. 칸 정의가 데이터라서 템플릿을 더하거나 저자가 칸을 바꿔도 DB 이전(migration)이 없다. 파일은 객체 스토리지의 같은 경로로 간다. Store 인터페이스에 메서드만 더하면 된다(아래 도구가 쓰는 것: `create_drawer`, `list_drawers`, `put_drawer_item`, `search`는 기존 hybrid_search, `trash_drawer_item`, `restore_trash`).

### 3. 템플릿과 칸

- 코드에 정의한다(`magus/drawers/templates.py`). 칸 정의는 `key`(저자에게 보이는 칸 이름), `type`, `required`, `title`(목록에 보일 칸, 하나), `list`(여러 값), `hint`다.
  - type: `text` | `longtext` | `number` | `year`(연도·연도 범위) | `date` | `ref`(문헌 key) | `chapter`(장 번호)
  - 값은 문자열로 저장한다. `number`·`year`는 형식만 검사한다(정렬·연표용).

| 템플릿 | 칸(* 필수, 첫 칸이 제목) |
|---|---|
| 인물 | 이름*, 원어 표기, 생몰, 소속·국적, 설명, 관련 문헌(ref, 여럿), 메모 |
| 장소 | 이름*, 원어 표기, 위치, 시기, 설명, 메모 |
| 사례 | 제목*, 시기, 장소, 요약*, 출처(ref 또는 글), 메모 |
| 수치 | 항목*(무엇의 수치), 값*, 단위, 기준 시점, 출처*(ref 또는 기관·자료명), 확인(확인함/미확인), 메모 |
| 용어 | 용어*, 원어, 정의*, 출처, 메모 |
| 연표 | 연도*(year), 사건*, 장소, 출처, 메모 |
| 빈 서랍 | 내용*(longtext), 메모 |

- **칸 더하기·빼기**
  - 만들 때: `drawer_create(…, add_fields=["별명"], drop_fields=["원어 표기"])`. 제목 칸은 뺄 수 없다.
  - 만든 뒤(3단계): 더한 칸은 선택 칸이다(기존 항목에 값이 없으므로). 뺀 칸은 지우지 않고 `retired: true`로 숨긴다. 항목의 값은 파일에 남고, 되돌리면 다시 보인다. 칸 이름 바꾸기는 모든 항목 파일의 키를 바꾸는 일이라 3단계에 둔다.
  - 1단계에서 만든 뒤 칸을 고치려면 운영자 CLI(`magus drawer fields …`)로 한다.

### 4. 도구 — 서랍 이름을 인자로 받는 범용 5개(21 → 26)

서랍마다 도구를 만드는 방식(`drawer_인물_add`)은 쓰지 않는다. 사용자마다 도구 목록이 달라지고, claude.ai가 도구 목록을 연결할 때 받아 두며, 이름 규칙(영문 접두어)과 instructions 조립(등록된 도구만 언급)이 깨진다.

| 도구 | 하는 일 | 설명 첫 문장(초안) |
|---|---|---|
| `drawer_list()` | 서랍 목록: 이름·템플릿·칸·항목 수, 최근에 쓴 것부터. 칸 정의도 준다 | "저자의 서랍(저자가 이름 붙인 칸 묶음) 목록. 넣을 곳을 되묻거나 서랍에 넣기 전에 먼저 부른다." |
| `drawer_create(name, template, add_fields?, drop_fields?)` | 서랍 만들기 | "저자가 새 서랍을 만들자고 분명히 말했을 때만 부른다. 이름과 템플릿(인물·장소·사례·수치·용어·연표·빈 서랍)을 저자에게 확인받은 뒤 부른다." |
| `drawer_put(drawer, values, item_id?, chapters?, ai_fields?, closes?)` | 항목 넣기·고치기(item_id가 있으면 준 칸만 바꾼다) | "저자가 그 서랍에 넣으라고 분명히 말했거나, 되물어 서랍을 고른 뒤에만 부른다. drawer는 drawer_list의 이름 그대로, values의 키는 그 서랍의 칸 이름이다. 저자가 말하지 않은 칸은 지어내지 말고 비워 둔다. 채웠다면 ai_fields에 적는다." |
| `drawer_search(query?, drawer?, chapter_number?, project_id?, k=8)` | 찾기(서랍 하나 또는 전체). chapter_number를 주면 그 장에 연결된 항목 | "서랍 항목을 찾는다. 생각·문체·문헌은 각자의 검색 도구로 찾는다." |
| `drawer_delete(drawer, item_id, note)` | 항목을 휴지통으로 | "저자가 그 항목을 지우라고 분명히 말했을 때만 부른다. 여러 개면 목록을 보여 주고 확인받는다."(idea_delete와 같다) |

- **헷갈리지 않게 하는 문장**: 다섯 설명 모두 끝에 "떠오른 생각은 생각(idea_add), 좋아서 모은 구절은 문체(style_add), 읽고 등록한 책·논문은 문헌(ref_add)에 넣는다. 서랍은 그 밖에 저자가 이름 붙인 것이다."를 둔다.
- 응답은 짧게: drawer_search는 항목마다 제목·서랍·핵심 칸 2~3개(각 120자)·연결된 장만 준다. 전체 칸은 item_id로 하나만 다시 부를 때 준다(`drawer_search(drawer, query=item_id)`).
- 서랍 통째 지우기는 1단계에서 도구로 두지 않는다(운영자 CLI만). 실수 한 번에 항목 수백 개가 사라지는 일을 막는다.

### 5. 되묻기 규칙 확장(규칙 9)

- 저자가 서랍 이름을 말하면("인물 서랍에", "수치에 넣어 줘") 그 서랍에 바로 넣는다. 세 코어 이름이 먼저다(이름 규칙으로 겹치지 않게 막는다).
- 넣을 곳을 말하지 않았으면 묻는다. 선택지는 **생각·문체·문헌 + 저자의 서랍**이다. 원고는 넣지 않는다(#90).
- 서랍이 많을 때 선택지 보이는 법
  - 서랍이 4개 이하: 모두 보인다. "생각·문체·문헌, 또는 서랍(인물·수치·연표) 중 어디에 넣을까요?"
  - 5개 이상: 세 코어 + **내용에 맞는 서랍 최대 3개**를 보인다. 맞춤은 Claude가 내용과 템플릿·칸으로 고르고, 같으면 최근에 쓴 순서다. 그리고 "그 밖의 서랍 N개" 한 줄을 붙여 저자가 "목록 보여 줘"라고 하면 전부 보인다.
  - 서버는 drawer_list를 최근 사용 순으로 주고 템플릿을 함께 줘서 Claude가 고르기 쉽게 한다. 서버가 자동으로 고르지는 않는다(저자가 고른다).
- instructions 규칙 9를 바꾸고 용어집(규칙 7)에 "서랍(저자가 이름 붙인 칸 묶음. 인물·장소·사례·수치·용어·연표 등)"을 더한다. 규칙 9는 `drawer_list`를 언급하므로 그 도구가 등록돼야 실린다(지금 구조 그대로).

### 6. 이름 규칙

- 정규화한 이름(`name_key`)으로 비교한다.
  - 정규화: NFC, 앞뒤 공백 제거, 공백 하나로, 라틴 문자는 소문자, 끝의 " 서랍"은 뗀다("인물 서랍" = "인물").
- 길이 1~20자. 글자·숫자·공백·`·`·`-`만 받는다. 숫자만은 안 된다.
- 금지(예약어)
  - 세 코어와 그 옛 이름: 생각·문체·문헌·영감·문체 취향·책장
  - 원고 쪽 이름: 원고·전체·확인 요청·미해결·결정·수정본·받은함·휴지통·서랍·장·책·책 지도
  - 내부 이름: Casper·Melchior·Balthasar·refs·idea·style·ref·book·drawer
- 같은 사용자 안에서 같은 이름(name_key)은 하나뿐이다. 휴지통에 있는 서랍 이름도 막는다(되살릴 때 겹치지 않게).
- 거부할 때 이유를 한국어로 말한다("'생각'은 고정된 이름이라 서랍 이름으로 쓸 수 없습니다").

### 7. 장 연결

- **연결(저장)**: 항목의 `chapters: [{project, number}]`. drawer_put의 `chapters=[12, 31]`(project_id를 빼면 현재 책)로 잇는다. 저자나 Claude가 명시한 것만 파일에 남는다.
- **언급(계산)**: 제목 칸(인물·장소·용어의 이름)이 장 본문에 나오는 곳. 파생값이라 인덱스(`drawer_item_mentions`)에만 둔다. 장 쓰기·수정본 올리기·reindex 때 다시 계산한다(인용 수 집계와 같은 시점). 두 글자 이하 이름은 오탐이 많아 세지 않는다.
- **장을 볼 때**
  - `book_read_chapter` 응답에 한 줄을 더한다: `drawer_items: {"연결": 3, "언급": 5, "서랍별": {"인물": 4, "수치": 4}}`. 목록은 싣지 않는다(응답을 짧게).
  - 자세히는 `drawer_search(chapter_number=12)`다.
- 수정본에서 장이 빠지면 연결은 그대로 두고, 화면에 "(없는 장)"으로 보인다. 장 번호는 "같은 번호 = 같은 장" 규칙(#76)을 따른다.

### 8. "수치" 서랍과 확인 요청(fact)

- 사실·수치 확인 요청(kind=fact, 최신본 82건)이 수치 서랍의 주 공급원이다.
- 흐름
  1. 저자가 수치를 확인한다(원자료를 보고).
  2. Claude가 수치 서랍에 넣는다: `drawer_put("수치", {항목, 값, 단위, 기준 시점, 출처, 확인: "확인함"}, chapters=[N], closes=["I46"])`.
  3. 서버는 항목을 저장하고, `closes`의 확인 요청을 닫는다. note는 `수치 서랍 「항목」에 확인 기록(<item_id>)`이다. 항목에도 `closes`로 남는다(양쪽에서 이어짐).
- 안전장치
  - `closes`는 열린 fact(또는 citation) 확인 요청만 받는다.
  - 설명에 적는다: "확인 요청을 닫기 전에 저자에게 '이 수치로 I46을 닫을까요?'라고 묻는다."
  - `값`·`출처`가 ai_fields에 있으면 `closes`를 거부한다. AI가 채운 수치로는 확인 요청을 닫지 않는다.
- 출처가 문헌 key면 그 문헌이 verified인지 함께 보여 준다(🟢/🟡). 수치 항목 자체를 인용 근거로 삼지는 않는다(1절).
- 확인 요청(book_issues) 쪽에서도 닫힌 note로 항목을 찾아갈 수 있다. 다시 올리기에서 같은 코멘트가 남아 있으면 지금처럼 "닫힌 채 둔다"(#76).

### 9. 휴지통

- 항목은 생각·문체와 같은 방식(#88)이다: `trash/drawers/<drawer_id>/items/`로 옮기고, `magus trash restore drawer <drawer_id>/<item_id>`로 되살린다.
- 서랍 통째는 운영자 CLI만 한다(`magus drawer trash <이름>`). 항목과 drawer.json을 함께 옮긴다.

### 10. 웹(읽기 전용, 세 책장 화면과 같은 방식)

- 메뉴 하나 "서랍"을 더한다. 서랍마다 메뉴를 만들지 않는다.
- `/drawers`: 서랍 목록(이름·템플릿·항목 수·최근 사용). 빈 상태 예문: `Claude에게 이렇게 말하면 만들어집니다. 예: "인물 서랍을 만들어 줘"`.
- `/drawers/{id}`
  - 항목 표: 칸이 열이 되고, 긴 값은 "더 보기"로 접는다. AI가 채운 칸에는 작은 "AI가 채움" 표시를 단다. 연결된 장도 보인다.
  - 100개씩 나눠 보이고, 장으로 거른다(`?chapter=12`). 연표는 연도순으로 정렬한다.
- 쓰기 폼은 두지 않는다(로그아웃만). 사용자 격리 시험을 둔다(같은 서랍 이름·같은 id인 두 사용자).

### 11. 시험(구현할 때)

- 격리: 두 사용자가 같은 서랍 이름·항목 id를 써도 섞이지 않는다(MCP·웹·reindex 뒤).
- 이름 규칙: 예약어와 정규화 충돌("인물 서랍" vs "인물") 거부. 오류 문장에 이유가 있는지 본다.
- 칸 검증: 모르는 칸 거부, 필수 칸, 수치 템플릿의 ai_fields 제한, closes 안전장치.
- `tests/test_author_terms.py`에 새 도구 다섯 개가 자동으로 들어간다(설명·응답에 내부 이름 없음).
- 장 연결과 언급 계산, 수정본 올린 뒤 언급 갱신.
