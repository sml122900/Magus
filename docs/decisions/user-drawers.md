# 저자의 카테고리(옛 이름: 서랍) — 최소 버전 구현

> **2026-10-07 바뀜(사용자 결정 #93)**: 아래 #92-a "카테고리는 사람 소유"는 [floors.md](floors.md)의 층 구조로 대신했다. 카테고리(기본 카테고리 포함)는 공용 층이나 한 작업물 층에 꽂히고, 층 사이를 옮긴다. 나머지(템플릿·이름 규칙·색·제목)는 그대로다.

- 날짜: 2026-10-06(초안 #91) → 2026-10-06 밤 고침·구현(#92, 야간 자율 작업)
- 상태: **최소 버전 구현, 검토 대기**(status.md 4절 #92의 "고른 것"들). 파일 이름은 링크 때문에 그대로 둔다. 문서 안의 "서랍"은 모두 "카테고리"로 바꿨다.
- 요청: 책장 화면에 생각·문체·문헌(기본 카테고리) 옆에 저자가 만든 카테고리를 꽂는다. 만들기·이름 바꾸기·색 바꾸기·휴지통은 책장 화면과 대화 양쪽에서. 항목 제목은 선택(저자가 짓기·AI가 짓기·비워 두기), 책 색은 저자가 정한다.
- 관련: [web-style.md](web-style.md)("책장 전용" 색), [store-interface.md](store-interface.md), [citation-gate.md](citation-gate.md), [instructions-from-registered-tools.md](instructions-from-registered-tools.md), [author-questions.md](author-questions.md)(#84), CLAUDE.md "저자에게 보이는 이름"(#85·#87·#90·#92)

## Problem

- 원고에는 구조가 있는 재료가 많다: 인물, 사례, 수치(사실·수치 확인 요청 82건), 용어. 지금은 넣을 곳이 생각(자유 메모)뿐이라 칸이 없고 장과 이어지지 않는다.
- 저자(고령의 교수)는 웹에서 "어디에 무엇이 있는지"를 한눈에 보고 싶어 한다. 메뉴 셋(생각·문헌·문체)과 표 목록으로는 그게 안 된다.
- 제약
  - 원본은 사람이 읽을 수 있는 파일, SQLite는 인덱스(언제든 다시 만든다). 모든 행에 user_id.
  - 도구 이름은 접두어로 묶고, 응답은 짧게. 카테고리마다 도구를 만들지 않는다(사용자마다 도구 목록이 달라지면 instructions 조립·claude.ai 캐시가 깨진다).
  - **누가 말했는지 보존한다.** LLM 기억에서 나온 사실·수치가 원고로 들어가는 통로가 되면 안 된다(왜 만드나 3번).
  - 저자에게는 용어집 이름만 보인다. 원고를 가리키는 "책"과 섞이지 않게 카테고리를 "책"이라고 부르지 않는다.

## Action — 고른 것

### 1. 기본 카테고리와 저자의 카테고리

| | 생각 | 문체 | 문헌 | 저자의 카테고리 |
|---|---|---|---|---|
| 이름·삭제 | 고정 | 고정 | 고정 | 저자가 만들고 이름 붙임, 휴지통 |
| 책 색 | 바꿀 수 있음 | 바꿀 수 있음 | 바꿀 수 있음 | 바꿀 수 있음 |
| 넣는 도구 | idea_add | style_add | ref_add | category_put |
| 특별한 동작 | me/ai 구분, 제목(선택) | 문체 자문 | **인용 게이트** | 없음. 인용 근거가 되지 않는다 |

- 카테고리는 **사람 소유**다(기본 셋과 같다). 책과의 관계는 항목의 장 연결로만 맺는다.

### 2. 저장(파일이 원본, 모두 `schema_version: 1`)

```
data/users/<user_id>/shelf/categories/<카테고리 id>/category.json      # {schema_version, id, name, template, color, fields, created_at, updated_at}
data/users/<user_id>/shelf/categories/<카테고리 id>/items/<항목 id>.json  # {schema_version, id, title, title_by, content, fields, author, tags, chapters, …}
data/users/<user_id>/shelf/settings.json                                # {schema_version, colors{ideas,styles,refs}, my_colors[≤12], title_default}
data/users/<user_id>/trash/shelf/categories/<카테고리 id>/              # 카테고리 통째(항목 포함, "_trash")
data/users/<user_id>/trash/shelf/category-items/<카테고리 id>/<항목 id>.json
```

- id는 서버가 짓는다(`new_id`, 시각 + 6자). 폴더는 id, 이름은 category.json에만 둔다. 이름을 바꿔도 파일을 옮기지 않는다.
- 칸 정의(fields)는 만들 때 템플릿에서 **복사**한다. 템플릿이 나중에 바뀌어도 이미 만든 카테고리는 그대로다.
- 인덱스(SCHEMA_VERSION 15): `categories(… name_key UNIQUE, schema_version)`, `category_items(… schema_version)`, 검색 레인 `category`(owner_id `<카테고리 id>/<항목 id>`), ideas에 `title`·`title_by`. 책장 설정은 작아서 파일을 바로 읽는다.
- **나중에 옮기기**: 파일과 인덱스 행에 schema_version이 있어서, 형식이 바뀌면 읽을 때 버전을 보고 옮긴다. Postgres(P2)에서는 `fields`·`chapters`가 jsonb로 그대로 간다. 칸 정의가 데이터라 템플릿을 더해도 DB 이전이 없다.

### 3. 템플릿(칸은 작게)

| 템플릿 | 칸(모든 항목에 제목·내용이 따로 있다) |
|---|---|
| 빈 카테고리 | 없음 |
| 인물 | 원어 표기, 생몰, 소속·국적 |
| 사례 | 시기, 장소, 출처 |
| 수치 | 값, 단위, 기준 시점, 출처 |
| 용어 | 원어, 출처 |

- 항목: 제목(선택), 내용, 템플릿 칸, 누가(`me` 저자의 말 / `ai` Claude가 쓴 글), 작성 시각, 태그(10개까지), 장 연결(선택, 지금 책의 장 번호. 없는 장은 거부).
- "수치와 확인 요청 연결"은 이번에 하지 않았다(요청대로). 수치·출처는 저자가 말했거나 확인한 것만 넣는다고 도구 설명에 적었다(서버가 막지는 않는다).

### 4. 이름 규칙(`magus/category/rules.py`)

- 같은 이름 판단: NFC, 공백 무시, 라틴 소문자, 끝의 "카테고리"는 뗀다("사례 카테고리" = "사례").
- 12자까지(책등에 세로로 들어가는 길이). 글자·숫자·띄어쓰기·가운뎃점·하이픈·괄호·&만. 숫자만은 안 된다.
- 예약어: 생각·문체·문헌·원고·전체·확인 요청·AI 확인 요청·결정·수정본·책장·카테고리·받은함·휴지통·인용 체크리스트·책, 옛 이름(영감·미해결·이슈·책 지도·새 판·서랍), 내부 이름(Casper·Melchior·Balthasar·idea·style·ref·book).
- 같은 사용자 안에서 같은 이름은 하나. 휴지통에 같은 이름이 있어도 새로 만들 수 있고, 되살릴 때 겹치면 `--name`으로 새 이름을 준다.
- 사용자마다 30개까지(기본 셋 빼고). 거부할 때는 이유를 한국어로 말한다.

### 5. 도구 7개(21 → 28)

`category_list`, `category_create`, `category_edit`(이름·색), `category_put`(넣기·고치기), `category_search`, `category_trash`(항목 또는 통째), `category_title_default`. 설명 문장 전문은 docs/daily/2026-10-06.md "새 도구".
- 쓰기 도구 설명 첫 문장은 "저자가 …라고 분명히 말했을 때만 부른다"다(#87과 같은 방식).
- 기본 카테고리에 category_put을 부르면 "idea_add로 넣는다"처럼 맞는 도구를 알려 주고 거부한다.

### 6. 되묻기와 제목(instructions 규칙 9·10)

- 넣을 곳을 말하지 않은 저장 요청에는 **생각·문체·문헌과 저자의 카테고리** 중 어디인지 묻는다. 카테고리가 많으면 목록을 보여 준다. 원고는 선택지에 없다(#90 그대로).
- 제목을 말하지 않았으면 저장하기 전에 직접 지을지·지어 드릴지·비워 둘지 묻는다. 저자가 "앞으로는 …"이라고 하면 `category_title_default`로 서버에 저장한다.
- **서버가 지킨다**: 제목 없이 idea_add·category_put을 부르면 기본값이 '매번 묻기'일 때 저장하지 않고 "먼저 묻는다"는 오류를, 'AI가 짓기'일 때 "지어서 다시 부른다"는 오류를 돌려준다. '비워 두기'면 그대로 저장한다. 그래서 대화 메모리에 기대지 않는다. 대화 기록 넣기(idea_add_conversation)는 묻지 않는다.
- AI가 지은 제목은 `title_by: ai`로 남기고 응답·검색·웹에 "AI가 지은 제목"으로 보인다. title_by를 빼면 ai로 남긴다(tags_by와 같은 보수적 기본값).

### 7. 웹(책장)

- `/shelf`: 양장본 책장. 기본 셋 + 저자의 카테고리, 마지막에 점선 "카테고리 추가". 책등 위 띠 = "기본" 또는 템플릿 이름(빈 카테고리는 "일반"), 아래 = 항목 수, 두께 = 항목 수 단계, 높이 = 카테고리마다 조금씩.
- 목록 위에 "이름·색 바꾸기"(기본 셋은 "책 색 바꾸기")와 "휴지통으로"(확인 화면 뒤 POST).
- 저자의 카테고리와 생각에는 "새로 적기" 폼(제목 선택·내용·칸). 적은 사람은 저자(me), 제목을 적으면 title_by=author. 문체·문헌은 대화로 넣는다.
- 색: 기본 색 18개 격자 + 내 색(12개까지, 뺄 수 있음) + 직접 고르기(색 선택기·#RRGGBB·R·G·B를 서로 맞춤). 서버는 `^#[0-9a-fA-F]{6}$`만 저장하고 그 밖의 문자열은 스타일에 넣지 않는다.
- 모든 POST는 CSRF. 카테고리 이름(글자 제한)·항목 내용은 모든 출력에서 이스케이프한다.

### 8. 휴지통

- 항목과 카테고리 통째를 지우지 않고 옮긴다. 되살리기는 운영자 CLI: `magus trash restore category <id> [--name 새 이름]`, `magus trash restore category-item <카테고리 id>/<항목 id>`.
