# 원고 프로젝트 삭제 보호 + 활동 기록 (2026-10-14, 사용자 결정)

## Problem

- 2026-10-11 00:13 KST, 아버님 원고 프로젝트(장 42 · 수정본 E3)가 웹 지도의 '🗑 휴지통으로'로 통째로 휴지통에 갔다. 확인 창은 '옮기기' 한 번이었다.
  같은 날 배포(`p1-batch-1011`)로 '휴지통 비우기'가 생겨, 그대로 두었으면 한 번 더 눌러 영구 삭제될 수 있었다(백업에만 남음).
- 언제 무슨 동작이 있었는지 알 길이 거의 없었다. HTTPS 접근 로그는 주소에 내려받기 토큰이 들어 있어 남기지 않고(Caddyfile `output discard`),
  서버 로그는 배포 때 컨테이너를 새로 만들며 사라졌다. 2026-10-13 되살리기 보고는 파일의 시각(manifest `at`, project.json `created_at`)으로 맞췄다.

## Action

1. **이름을 적어야 옮기고 지운다.** 올린 문서가 든 프로젝트(장이나 수정본 기록이 있는 것)를 휴지통으로 옮길 때, 확인 창에
   "이 프로젝트에는 올린 문서(장 N개 · 수정본 EN)가 있습니다." 한 줄과 이름 칸을 두고, 이름을 그대로 적어야 [옮기기]가 켜진다.
   휴지통에서 그런 프로젝트와 휴지통의 올린 문서(책 설정 🗑으로 옮긴 것)를 영구 삭제할 때도 같다. 책 설정의 올린 문서 휴지통도 같은 칸.
   - 규칙은 서버(`store.base.same_name`)가 다시 본다: 공백 차이·앞뒤 따옴표(「」 등)·한글 조합 형태(NFC)만 같게 보고, 틀리면 아무것도 옮기지 않는다.
     화면의 버튼 켜기(`webtrash.NAME_SCRIPT`)는 같은 규칙의 편의일 뿐이다. 저장소 메서드(`trash_project`·`trash_manuscript`·`purge_trash`)가
     `confirm_name`을 받으므로 웹이 아닌 길(CLI 등)도 이름 없이는 옮기지 못한다.
2. **'휴지통 비우기'는 그것을 빼고 비운다.** 비운 뒤 "올린 문서가 든 프로젝트 N개는 남겼습니다."(올린 문서는 "올린 문서 N개")로 알리고,
   비우기 확인 창에도 미리 "…는 남깁니다."를 보인다. 그것은 줄마다 이름을 적어 하나씩 지운다.
3. **대화(category_trash)로는 프로젝트를 옮기지 못한다.** 이미 막혀 있었다(가운데 노드는 MapError center, 올린 문서가 든 책은 거절,
   프로젝트를 고르는 인자가 없다). 시험으로 고정했다(`tests/test_guard_project.py`).
4. **활동 기록**(`magus/activity.py`): 휴지통으로·되살리기·영구 삭제·휴지통 비우기·프로젝트 만들기·문서 업데이트가 일어나면
   사용자 폴더의 `.activity.log`에 `시각(UTC) · 동작 · 대상 종류 · 대상 id · 경로(웹·대화·운영자)` 한 줄.
   - 저장소 메서드에 데코레이터(`@logged`)를 붙였다. 웹 처리기·도구마다 적으면 빠뜨리기 쉽다. 경로는 contextvar(`activity.VIA`):
     웹은 `Web._wrap`, 대화는 MCP 미들웨어(`audit.ToolCallLog`)가 정하고, 그 밖(CLI)은 '운영자'.
   - 한 동작 안에서 저장소가 다른 동작을 부르면(노드째 휴지통 → 책, 올린 문서 휴지통 = 옮기기 + 같은 id의 빈 프로젝트 만들기) 바깥 동작 한 줄만
     (스레드마다 `busy` 표시). 문서 업데이트는 저장소 밖의 한 동작이라 `activity.step`으로 감싸 한 줄.
   - 이메일·제목·본문·파일 이름은 넣지 않는다. 대상은 id만(올린 파일은 이름 대신 휴지통 id). 90일 지난 줄은 다음 기록 때와 서버를 띄울 때 지운다.
     사용자 폴더 안이라 restic 백업에 들어간다. 기록이 실패해도 동작은 막지 않는다(경고 로그에 예외 종류만).
   - 확인 방법은 `docs/deploy.md` 5절 첫 줄.

## Result

- 시험: `tests/test_guard_project.py`(6) · `tests/test_activity.py`(5) 새로, 기존 휴지통 시험은 이름을 적게 고침. 전체 결과와 배포는 status.md 0-41절.
- 화면 문구: 확인 창 한 줄 + "확인을 위해 이름을 적어 주세요: 「이름」", 비우기 뒤 "…는 남겼습니다.", 이름이 틀리면
  "이름이 맞지 않아 영구 삭제하지 않았습니다…"(옮기기는 "프로젝트 이름이 맞지 않아 휴지통으로 옮기지 않았습니다…").

대안을 버린 이유: 비우기에도 이름 칸을 두면(여러 이름을 한 번에 적기) 실수 여지가 남고 화면이 무거워진다. 빼고 비운 뒤 남긴 수를 알리는 쪽이 더 안전하다.
웹 처리기에서만 기록하면 대화·CLI 길이 빠지고, 서버 로그에 남기면 배포 때 사라진다.
