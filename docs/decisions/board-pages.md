# 책 = 게시판 페이지, 첨부로 수정본, 웹에서 글 고치기·원문 확인 체크 없앰(2026-10-09, 사용자 요청 #98)

## Problem
- 지도 옆 패널 안에 책의 게시판을 iframe으로 띄웠다(#95). 패널이 좁아 휴대폰에서 답답하고, 주소 하나(`/shelf/p/<프로젝트>?node=&book=&at=`)에 상태가 몰려
  주소창으로 연 책 화면을 지도로 되돌리는 넘기기, iframe 안 머리 없는 화면(EMBED), iframe에서 바깥으로 나가는 장치까지 필요했다.
- 문서를 넣는 길이 셋이었다: 책장의 '책 추가 → 문서 올리기', 올린 문서의 '수정본 올리기' 폼, 내 정보의 '올린 파일' + 대화. 저자에게 어디서 올리는지 설명이 길었다.
- 게시판 글의 고치기·원문 확인 체크(#97)는 웹에서 하는 일을 늘렸다. 저자는 쓰기·보기·지우기만 원했고, 고치기는 대화로 충분하다.
- 도움말 창의 대화는 페이지를 옮기면 사라졌다.

## Action
- **책은 별도 페이지의 게시판**(`magus/webboard.py`): 위치 표시(프로젝트 › 프로젝트 이름 › 노드 › 책), 한 줄 = 제목 · 📎(그림이면 미리보기) · 날짜,
  최신 글 위, 20개씩, 오른쪽 위 '글쓰기' 하나. 글쓰기(끌어다 놓기·고르기·휴대폰 사진 찍기)와 글 보기(본문·사진·파일 목록·🗑)도 각자의 페이지.
  지도에서 책은 보통 링크다. iframe·EMBED·넘기기를 걷어 내고, 옛 `?at=` 주소는 그 페이지로 넘긴다.
- **문서·수정본은 게시판 첨부로**: 글의 첨부 중 docx·pdf·md·txt를 files_list가 `첨부:<id>`로 보이고, 도구의 파일 인자를 푸는 한 곳(FileResolver)이 그 이름을 받는다.
  저자가 "수정본 올렸어"라고 하면 Claude가 files_list에서 마지막 업로드보다 나중의 문서를 찾아 `book_import(new_edition=true)`. instructions 규칙 7의 수정본 문장을 이에 맞췄다.
  첫 문서는 프로젝트 목록의 '+ 프로젝트'에서 올리는 길만 남겼다.
- **웹은 쓰기·보기·지우기만**: 글 고치기와 원문 확인 체크를 없앴다(데이터·MCP 도구는 그대로). 글 지우기는 노드와 같은 방식(🗑 → 화면 안 확인 창 → 휴지통),
  되살리기는 프로젝트 휴지통 화면에 노드와 함께.
- **도움말 대화는 브라우저에 보관**: localStorage, 로그인한 사용자별 열쇠(이름의 해시), 20턴·24시간·새 대화·로그아웃 때 지움. 서버 저장 없음.
- 비교한 대안
  - 패널 iframe을 넓히기: 주소·상태 문제와 휴대폰 문제가 그대로다.
  - 웹에 '문서 올리기'·'수정본 올리기'를 남기기: 길이 셋이 그대로라 설명이 길다. 첨부 하나로 모으면 웹·대화 모두 같은 파일 목록(files_list)을 본다.
  - 첨부 전용 새 도구(attachment_read 등): 도구 수·instructions가 늘고 커넥터 설명이 길어진다. 파일 인자 해석 한 곳만 바꾸면 기존 세 도구가 그대로 받는다.
  - 도움말 대화를 서버에 저장: 질문·답을 남기지 않는다는 원칙(로그·저장 없음)에 어긋난다.

## Result
- 시험 337 통과(게시판 4·글 휴지통 2·도움말 보관 4 새로, 격리 포함). 저장 형식은 바뀌지 않아 데이터 이전이 없다.
- 시험본(default·father-trial 복사본, 이전 뒤): 옛 코드(p1-razor)와 새 코드의 문헌·미확인·미연결·확인 요청·수정본 수가 같다(299·297·0·86 / 337·335·1·129·E1).
  새 코드로 게시판·글 보기·휴지통을 돌고 글을 휴지통에 넣었다 되살린 뒤 사용자 폴더 파일 해시가 복사 직후와 같다.
- 웹 모듈에서 iframe 관련 코드(지도 스크립트의 책 패널, EMBED, 바깥으로 나가기, 주소창 넘기기, locate)와 글 고치기·체크 처리기를 지웠다.
- 남은 판단은 status.md 4절 #98 표(원문 확인 표시를 떼는 길이 없어짐, 첨부 하나만 빼기 없어짐 등).

대안을 버린 이유: 패널 iframe은 상태·휴대폰 문제가 남고, 올리기 길을 여럿 두면 설명이 길며, 첨부 전용 도구는 도구·instructions만 늘린다.

## 되돌림(2026-10-09, 같은 날)
- **글 고치기를 다시 넣었다. 저자 요청: 고칠 길이 없으면 불편하다.** 글 보기의 '고치기'(🗑 휴지통으로 옆) → 글쓰기와 같은 화면(제목·본문·첨부가 채워진 채).
  바꾼 칸(제목·본문·고친 시각)만 파일에서 고치고 나머지 칸은 바이트까지 그대로 둔다(`Store.patch_category_item`, 문헌 글은 `set_ref_memo`).
  기존 첨부마다 ✕(빼기 → 휴지통, 프로젝트 휴지통에서 그 글로 되살린다). 원칙: 웹에서 없애는 것은 모두 휴지통을 거친다. 원문 확인 체크는 여전히 웹에 없다.
