# 모든 동작을 책장에서 — 책 종류(원고·모음·문서) — 사용자 결정 #94 (2026-10-07)

> 층(#93) 위에 얹는다. 책장에 꽂히는 것을 **책** 하나로 부르고 종류를 셋으로 나눈다: 원고 책 · 모음 책 · 문서 책.
> 구현: `src/magus/webbooks.py`(책 추가·원고 책·문서 책 화면), `src/magus/book/documents.py`(출처 확인 문서), `src/magus/book/document_tools.py`(book_document),
> `src/magus/store/documents.py`(문서 책 저장), `src/magus/mdlite.py`(문서 표시). 화면 문구 전문 `bookshelf-ui-texts.md`, 도구·instructions 전문 `bookshelf-tool-texts.md`.
> **로컬만, 서버 배포 없음.** 층 작업(`floors-local`)과 묶어 한 번에 배포한다(`docs/deploy.md` 2-2절). 검토 대기 표는 status.md 4절 #94.

## Problem

- 층(#93)으로 "어느 작업물의 것인지"는 보이게 됐지만, 할 일은 여전히 메뉴 다섯 곳(원고·받은함·인용 체크리스트·확인 요청·책장)에 흩어져 있었다.
  원고를 올리려면 받은함에 올리고 → 원고 화면에서 프로젝트 id를 적어 가져와야 했다. 빈 층을 채우는 안내도 "프로젝트 id 칸에 이 층의 id"였다.
- 저자 확인 보고서(author-report)는 운영자가 CLI로 만들어 docx로 보냈다. 저자가 Claude에게 "정리해서 넣어 줘"라고 해도 넣을 곳이 없었고,
  Claude가 수치·목록을 대화에 옮겨 쓰면 틀릴 수 있다(#3: 인용 270개가 LLM 기억에서 나왔다).
- 제약: 도구 목록 토큰 10,957 이하(층 작업 끝 기준), 템플릿 엔진·외부 라이브러리 없음(#56), 실사용자 공간 불변, 저자에게 보이는 글은 용어집 이름만, 주 사용자는 고령의 교수.

## Action

**책 종류**
- 원고 책: 원고 파일에서 만든 책. **층 하나에 원고 책 하나**이고 원고 책이 곧 그 층이다(옮길 수 없다). 장·확인 요청·인용 상태·수정본 이력이 들어 있다.
  휴지통으로 보내면 원고(장·확인 요청·결정·수정본 이력)만 휴지통으로 가고 층과 다른 책은 남는다(같은 id의 빈 층).
- 모음 책: 지금의 카테고리(생각·문체·문헌 + 저자의 카테고리). 공용 층에는 모음 책만 둔다.
- 문서 책: 원고에서 만든 읽기용 문서. 만든 때의 사진이다(기준 원고·수정본 번호·만든 시각·만든 방법을 적는다). 첫 종류는 **출처 확인 문서**.
- 책등 위 띠에 종류(원고·모음·문서)를 쓴다. 색·이름·옮기기·휴지통은 종류와 상관없이 같은 '책 설정'에서 한다(원고 책은 옮기기만 없음).

**책 추가**(층마다 점선 자리) → 세 갈래
- 원고: 파일을 고르면 받은함을 거치지 않고 바로 가져온다(진행 막대: 올리는 중 % → 가져오는 중). 원본은 그대로 그 원고의 original/에 복사된다.
- 모음: 이름·템플릿·색(기존 화면 "모음 책 만들기").
- 문서: Claude에게 할 말을 보여 준다(문서는 대화에서 만든다).

**원고 책 화면**: 탭 넷(장 목록 · 확인 요청 · 인용 상태 · 수정본 이력). 수정본 올리기는 수정본 이력 탭 안. 옛 주소는 새 화면으로 넘긴다.
상단 메뉴는 **책장** 하나. 받은함은 내 정보 아래 **올린 파일**(`/me/files`)로 옮겼다. 논문으로 문헌 등록은 문헌 목록 안(접힌 칸).

**문서 책 — 출처 확인 문서**
- 절: 한눈에 / 1 답해 주실 질문 / 2 원고 불일치 / 3 사실·수치 확인 요청 / 4 원문 확인 우선 문헌 / 5 장별 미확인 문헌 수 / 6 이전 수정본 대비 바뀐 점.
  내용은 서버가 데이터로 만든다(저자 보고서 생성기를 절 단위로 나눠 함께 쓴다. 나눈 뒤에도 저자 보고서 출력은 글자 하나 다르지 않음을 시험 사본 둘로 확인).
  Claude는 머리말(preface, 2,000자까지)만 넣을 수 있고 "Claude(AI)가 쓴 머리말입니다."로 표시된다.
- 기준 원고에 새 수정본이 오면 책등과 문서 화면에 **옛 판 기준**. "다시 만들기"는 지금 원고로 새로 만들고 이전 것은 '만든 이력'으로 남는다.
- docx 내려받기(기존 pandoc 경로), PDF는 브라우저 인쇄(인쇄용 CSS). 답하고 닫는 일은 문서가 아니라 원고 책의 확인 요청에서 한다.
- 저장: `shelf/documents/<id>/document.json` + `v1.md, v2.md…`(사람이 읽는 파일). 인덱스 v19 documents 표 + 책장 검색 레인(웹 전용).

**도구**(29개, 토큰 10,957 → 10,904)
- 더함: `book_document(kind, project_id?, floor?, title?, title_by?, untitled?, preface?, document_id?)`. 설명 첫 문장은 다른 쓰기 도구와 같이 "저자가 … 분명히 말했을 때만 부른다".
- 뺌: `idea_delete`·`style_delete` → `category_trash`(category=생각·문체 + item_id)로 합침. 이름이 바뀐 도구는 없다.
- 층 인자 설명을 줄였다("정하는 법은 instructions의 층 규칙"). 도구 문장의 '받은함'은 '올린 파일'로.
- instructions: 규칙 7에 책장·층·책(원고 책·모음 책·문서 책) 용어, 쓰지 않는 말에 '받은함'·'인용 체크리스트'.
  규칙 8 '수정본 올렸어'는 먼저 전체 현황의 수정본 줄을 본다(책장에서 올렸으면 이미 처리됨). 규칙 13(새): "…로 만들어 책장에 넣어 줘"의 흐름.
