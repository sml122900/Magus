### 웹 로그인 오류 문구 결함 수정
- 전에는 토큰이 무효(401)여도 화면이 "허용 목록에 없는 사용자"였다. 설정 문제(aud 불일치 등)를 허용 목록 문제로 오해하게 했다.
- `JwtVerifier.check(token) → (claims, reason)`
  - PyJWT 예외를 원인 힌트로 바꾼다: 만료·nbf·iss 불일치·aud 불일치·서명·필수 클레임·알고리즘·kid/JWKS·형식. 하위 클래스를 먼저 본다(InvalidSignatureError ⊂ DecodeError).
  - 검증하지 않고 읽은 iss·aud·exp·kid·alg를 함께 적는다. 토큰 값과 서명은 적지 않는다.
- 웹 콜백
  - 401: "로그인 토큰을 받아들이지 못했습니다(401). 원인은 서버 로그". 로그는 `web login: token rejected (<원인>)`.
  - 403: "허용 목록에 없습니다(403)"와 **본인 사용자 id**. 로그는 sub 해시.
- `ALLOWED_USERS`가 비어 있어도 시작한다(경고, 모두 403). 첫 로그인으로 id를 얻는 단계에 쓴다.

## 막힌 것과 해결
- **SSH 키에 암호가 있고 ssh-agent가 Disabled**: 관리자 창에서도 서비스 설정이 거부됐다. 사용자가 직접 agent를 켜고 키를 등록했다. 만들었던 임시 배포 키는 쓰지 않고 지웠다.
- **Git Bash의 ssh가 한글 사용자 폴더를 깨뜨림**(`/c/Users/\300…`): Windows OpenSSH(`/c/Windows/System32/OpenSSH/ssh.exe`)를 쓴다. Git Bash에서 불러도 agent가 된다.
- **`docker compose exec`가 `ssh … 'bash -s'`의 표준입력을 먹음**: 그 뒤 명령이 실행되지 않았다. 운영 스크립트의 exec·run에 `</dev/null`을 붙였다(`21b4e2a`).
- **outline 시각이 9시간 어긋남**: 컨테이너가 UTC였다. compose에 `TZ: Asia/Seoul`(`0c8e089`).
- **`docker compose logs --since`가 `+0900`을 못 읽음**: RFC3339 `+09:00`으로 준다.
- **git 경로 검사가 한글 파일을 놓칠 수 있음**: `core.quotepath`가 켜져 있으면 경로를 따옴표로 감싼다. 검사는 `git -c core.quotepath=false`로 한다. 이 설정으로 이력을 다시 확인했고, 결론은 바뀌지 않았다.
