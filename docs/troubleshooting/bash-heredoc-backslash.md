# Bash 도구의 heredoc에서 `\\`가 `\`로 줄어들어 코드 치환이 실패함

- 날짜: 2026-10-03
- 단계: 1단계 검토 반영 중

## 문제상황

- 여러 파일을 한꺼번에 고치려고 Bash 도구에서 `python - <<'EOF' … EOF` 스크립트로 문자열 치환을 했는데, 두 번 실패했다.
  1. `outline.py` 치환: 찾을 문자열에 `f"# {project.title}\\n"`을 썼는데 `count=0`으로 일치하지 않았다.
  2. `test_store.py`에 추가한 테스트: `"고친 본문\\n\\n둘째 문단"`을 썼는데 파일에는 실제 줄바꿈이 들어갔다. pytest 수집 단계에서 `SyntaxError: unterminated string literal`이 났다.
- 따옴표로 감싼 heredoc(`<<'EOF'`)은 POSIX상 백슬래시를 그대로 넘겨야 한다. 그래서 원인이 바로 보이지 않았다.

## 시도한 것들

1. 대상 파일을 다시 읽어 공백·특수문자(·) 차이를 의심했다. 원문과 패턴이 같아 보였다.
2. 최소 재현을 해 봤다.
   - `cat <<'EOF' | od -c`에 `a\\nb`를 넣었더니 `a \ n b`가 나왔다. 백슬래시가 하나로 줄었다.
   - `python - <<'EOF'`로 `print(repr('x\\ny'))`를 실행했더니 `'x\ny'`가 나왔다. Python에 `\n`이 넘어가 줄바꿈이 됐다.
3. 결론: 이 환경의 Bash 도구 경로에서는 따옴표 heredoc 안의 `\\`도 `\`로 줄어든다. 셸 문법이 아니라 도구가 명령을 전달하는 과정에서 일어나는 일로 보인다.

## 최종 해결법

- 백슬래시 이스케이프(`\n`, `\\`, 정규식)가 들어간 소스 코드는 heredoc 스크립트로 치환하지 않는다. **Edit/Write 도구로 직접 고친다.** 두 실패 모두 이렇게 해결했다.
- heredoc 치환은 백슬래시가 없는 단순 문자열에만 쓴다. 치환 함수는 `count != 1`이면 멈추도록 해서 조용히 실패하지 않게 한다(이번에도 이 검사 덕분에 바로 발견했다).

## 이력서 소재 한 줄

증상(치환 불일치, 구문 오류)에서 최소 재현(`od -c`)으로 도구 계층의 이스케이프 처리 문제를 분리해 내고, 편집 경로를 바꿔 재발을 막았다.
