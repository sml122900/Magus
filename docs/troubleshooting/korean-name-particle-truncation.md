# 조사 제거가 한국어 실명을 자름 (김성은 → 김성)

- 날짜: 2026-10-03 (실원고 보정 라운드)

## 문제상황

- 4단계에서 "갤러는(2022)"처럼 저자 뒤에 조사가 붙은 인용을 해석하려고 조사(은·는·이·가·의·을·를·와·과·도·에·로·만 …)를 떼는 규칙을 넣었다. 합성 데이터에서는 잘 동작했다.
- 실원고의 `김성은·테르틸트·염민철(2024)`에서 대표 key가 `김성2024`가 됐다. "은"을 조사로 보고 뗀 것이다.
- 같은 규칙이면 `카를로` → `카를`, `호프만` → `호프`처럼, 이름이 조사와 같은 글자로 끝나는 경우가 모두 망가진다.

## 시도한 것들

1. 실원고 본문에서 한글 서술형 인용을 모두 모았다. 실제로 "이름 + 조사(" 형태는 **한 건도 없었다**. 한국어 문장에서 조사는 보통 괄호 뒤에 온다("갤러(2022)는").
2. 원형을 첫 후보로 두는 기존 구조 덕분에 해석(refs 연결)은 이미 맞았다. 하지만 미확인으로 보고되는 대표 key가 틀린 이름으로 나왔다.
3. 조사 목록을 줄이는 방향으로 고쳤다. 남긴 것은 이름 끝에 올 수 없는 것(는·를·에서·에게·으로·처럼·보다·까지·부터·조차)뿐이다. 은·이·가·의·도·로·만·와·과는 뺐다.
   - "와·과"는 공저자 연결(애쓰모글루와 로빈슨)로 따로 처리한다.

## 최종 해결법

- `citations.py`의 `_PARTICLES`를 줄였다. 테스트에 `김성은·테르틸트·염민철(2024)` → `김성은2024`, `카를로(2010)` → 후보 `카를로2010`을 넣었다.
- 교훈: 합성 데이터로 만든 규칙은 실데이터 분포를 보고 다시 판단해야 한다. 이번에는 규칙이 겨냥한 형태(조사 붙은 인용)가 실원고에 0건이었고, 부작용(실명 훼손)만 있었다.

## 이력서 소재 한 줄

합성 데이터로 만든 휴리스틱을 실데이터 분포로 재검증해, 목표 사례는 0건이고 부작용만 있던 규칙(한국어 실명 훼손)을 찾아 최소화했다.
