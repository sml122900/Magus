# 아버지 온보딩 체크리스트 (7단계)

> 2026-10-06 갱신: 최신본 원고(`261005-인류가_선택한_진화_시대가_선택한_도시_원고.docx`) 수치와 새 작업 방식(결정 #68)을 반영했다.
> 아버지께 드릴 안내 자료는 채팅 Claude가 이 문서를 바탕으로 다시 만든다. 이 문서는 운영자용이다.
> 아버지 계정은 `father` 사용자다. 운영자의 `default`(개발용 PDF 임포트본)와 데이터가 섞이지 않는다.
> 아버지께 보이는 이름(사용자 결정 #85): **전체**(책 전체 현황) · **확인 요청** · **생각** · **문체** · **문헌** · **결정** · **수정본**(번호 E2, E3…는 수정본 번호). 안내 자료와 대화도 이 이름으로 한다(CLAUDE.md "저자에게 보이는 이름").

## 작업 방식(결정 #68)

- **원고의 원본은 아버지의 Word 파일이다.** Magus에 있는 원고는 마지막으로 올린 판의 사본이다.
- 아버지는 Word에서 고친다. 막히거나 표현을 묻고 싶으면 Claude와 대화한다. Claude는 Magus로 책 전체 맥락(목차·결정·확인 요청·그 장)을 보고 조언한다.
- Claude의 수정안은 대화로 받고, 아버지가 Word에 반영한다. 아버지가 "Magus에 저장해 줘"라고 분명히 말할 때만 Claude가 Magus 원고를 고친다(서버 규칙 4, #74).
- 떠오른 생각과 읽은 논문은 Magus에 쌓는다(생각·문헌). 좋아서 모은 구절은 문체에 쌓는다.
  - 어디에 넣을지 말하지 않고 "저장해 줘"·"기록해 줘"라고만 하면 Claude가 생각·문체·문헌 중 어디인지 먼저 묻는다(서버 규칙 9, #85).
- Word에서 고친 원고는 **수정본으로 올린다**(D절). 바뀐 장만 바뀌고, 결정·확인 요청·쌓아 둔 생각과 문헌은 그대로다.

## 순서(2026-10-05 결정)

1. 운영자 본인 → `default`로 먼저 연결해 6단계를 시험한다(docs/deploy.md 2-1절).
2. 아버지는 그 뒤 **`father`로 따로 추가**한다.
3. 아버지 원고는 **docx 원본을 아버지 받은함에 새로 임포트**한다. `default`의 PDF 임포트본은 옮기지 않는다.

## 0. 7단계 전에 확인할 것

- [ ] **서버에 master 배포**(사용자 승인 대기): 새 파서(표·제N부 들어가며·코멘트 작성자·제목/부제)와 다시 올리기가 서버에 있어야 한다. 절차는 docs/deploy.md "업데이트". 배포 뒤 `/book`에 "원고 올리기"(수정본/새 책 선택)가 보이는지 본다.
- [ ] **받은함 화면 검토**(결정 #56 보완): 사용자가 `/inbox` 업로드 화면을 캡처해 채팅 Claude와 검토한다. 아버지가 혼자 올릴 수 있는지 본다.
- [x] **docx 크기 확인**(결정 #54 보완): 최신본 1.4MB(한도 `MAX_UPLOAD_MB` 50MB 안). 수정본을 받을 때마다 크기를 본다. 넘으면 서버 `.env`에서 올리고 `sudo docker compose up -d`.

## A. 운영자가 할 일

- [x] WorkOS(**Staging**, 결정 #49)에 아버지 계정을 만들었다(2026-10-06, 가입은 꺼져 있다). 로그인 방법은 이메일 코드(Magic Auth)다.
- [x] 아버지 사용자 id: WorkOS 대시보드에서 받았다(403 화면으로 얻는 단계는 생략, 2026-10-06).
- [x] 서버 `.env`에 `ALLOWED_USERS=<운영자 id>=default,<아버지 id>=father`를 넣고 `sudo docker compose up -d`를 실행했다(2026-10-06 02:17, 로그 "허용 2명").
  - 넣기 전에 확인한다: 새 id가 기존 id와 다르고, 이름이 서로 다르며(default·father), 한 이름에 sub가 둘 붙지 않았다.
- [ ] 아버지가 다시 로그인해 `/book`이 비어 있는 것을 확인한다.
- [ ] **비인용 용어 넣기**: `default`의 book 프로젝트에 넣었던 용어 5개(선하이정·마닐라·유조프카·푸둥·모스크바 회사)는 프로젝트별 파일이라 따라오지 않는다. 최신본 제27장 표의 `상트페테르부르크(1703)`도 지명이라 함께 넣는다(#81). 임포트한 뒤 아래를 실행한다. 수정본으로 올려도 이 목록은 그대로 남는다.
  ```sh
  sudo docker compose exec -e USER_ID=father magus /app/.venv/bin/magus terms --project-id book --add 선하이정 마닐라 유조프카 푸둥 "모스크바 회사" 상트페테르부르크
  ```
- [ ] 아버지 보고서 답변(음역 추정, `셰 등(2019)`이 Hsieh 2019 두 편 중 어느 것인지(#82) 등)을 확정할 때는 아버지 책장에 넣는다.
  ```sh
  sudo docker compose exec -e USER_ID=father magus /app/.venv/bin/magus alias <key> <표기>
  ```

## C. 첫 세션 대본 (Claude에서)

1. **전체**: "Magus로 전체 보여 줘"
   - 목차, 미확인 문헌 수, 확인 요청 수, 처음 올린 원고(E1)와 올린 시각이 나온다. "모든 작업은 여기서 시작합니다"라고 알려 드린다.
2. **제12장 인용 점검**: "제12장 인용 중 확인 안 된 것 알려줘"
   - 문헌 목록과 문단 번호가 나온다(최신본 시험: 미확인 37편). 확인할 문헌 하나를 고른다.
3. **논문 1편 등록**
   1. 그 논문 PDF를 문헌이 든 책(예: 「문헌」)의 '원문을 확인한 논문·책 넣기'에서 올리거나, 내 정보 → 올린 파일에 올린다.
   2. (올린 파일에 올렸으면) Claude에서 이렇게 말한다: "올린 파일 <파일명>.pdf를 「문헌」 책에 원문 확인으로 넣어 줘. 쓸 부분은 「…」, 이유는 …"
   3. 기대: 그 문헌 글에 '원문 확인' 표시가 붙고, 그 문헌이 나오는 장 목록이 나온다. 올린 원고의 '인용 상태' 탭에서 바뀐 것을 함께 본다.
      (#96: 「문헌」 책에는 컨텍스트 「논문」이 붙어 있다. AI는 이 책의 글을 그 설명대로 읽는다.)
4. **수정안은 Word에**: "제12장 첫 문단을 더 짧게 다듬어 줘"라고 해 본다. Claude가 수정안을 대화로 내고, Magus 원고는 바꾸지 않는 것을 함께 본다. 고친 문장은 아버지가 Word에 넣는다.

## D. 원고를 고친 뒤 수정본 올리기

- Word에서 고친 원고 파일을 `/inbox`에 올린다(파일 이름은 달라도 된다).
- `/book` → "원고 올리기"에서 그 파일을 고르고 **수정본으로 올리기**, 프로젝트 id `book` → **올리기**.
  - 파일을 올린 뒤 Claude에게 "수정본 올렸어"라고만 해도 된다. Claude가 받은함에서 가장 최근에 올린 원고를 이 책의 수정본으로 올린다(book_import `new_edition=true`). 마지막 업로드 뒤에 올린 원고가 여럿이면 어느 것인지 묻는다(서버 규칙 8).
- 결과 리포트에서 볼 것
  - 수정본 번호(E2, E3…), 본문이 바뀐 장과 그대로인 장, 새 장·빠진 장(빠진 장은 지우지 않고 보관), 제목이 바뀐 장
  - 원고 코멘트: 이어진 것, 새로 생긴 것, **해결됐을 수 있음**(원고에서 코멘트가 지워졌거나 걸린 문장이 없어진 것). 자동으로 닫지 않는다. 아버지와 확인하고 닫는다.
  - "Magus에서 고친 뒤 이번 수정본으로 덮인 장"이 있으면, 그 내용이 Word에 들어갔는지 확인한다(이전본은 Magus에 남아 있다).
- 장 제목이 기존 원고와 30% 미만으로 겹치면 다른 책으로 보고 멈춘다. 같은 책이 맞으면 "(수정본) 장 제목이 많이 달라도 같은 책으로 올리기"를 체크한다.
- **"같은 id가 있으면 바꾸기"(replace)는 쓰지 않는다.** 결정·확인 요청까지 휴지통으로 간다(운영 규칙 #78).
- 시험 결과(로컬, `reupload-trial`): 4판(E1, 코멘트 86) → 최신본(E2)에서 바뀐 장 6만 교체, 기존 확인 요청 86 유지 + 새 43, 결정·생각 그대로.
- Claude가 보는 전체(book_outline)에는 마지막으로 올린 시각이 나온다. 7일이 지나면 Claude가 "그사이 Word에서 고치셨으면 최신본을 올려 주세요"라고 먼저 묻는다.

## 확인할 것(위험)

- 다음 날 같은 대화에서 다시 불러 본다. 로그인을 다시 하라고 하면 운영자에게 알린다(토큰 갱신 문제, auth-provider.md 위험 항목).
- 장을 하나 끼워 넣어 번호가 밀린 판을 올리면, 지금은 같은 번호를 같은 장으로 보고 바꾼다(이전본은 보관, 확인 요청은 걸린 문장을 따라간다). 리포트의 "제목이 바뀐 장"이 많으면 운영자가 확인한다.
