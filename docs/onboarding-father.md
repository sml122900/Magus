# 아버지 온보딩 체크리스트 (7단계)

> 2026-10-06 갱신: 최신본 원고(`261005-인류가_선택한_진화_시대가_선택한_도시_원고.docx`) 수치와 새 작업 방식(결정 #68)을 반영했다.
> 아버지께 드릴 안내 자료는 채팅 Claude가 이 문서를 바탕으로 다시 만든다. 이 문서는 운영자용이다.
> 아버지 계정은 `father` 사용자다. 운영자의 `default`(개발용 PDF 임포트본)와 데이터가 섞이지 않는다.

## 작업 방식(결정 #68)

- **원고의 원본은 아버지의 Word 파일이다.** Magus에 있는 원고는 마지막으로 올린 판의 사본이다.
- 아버지는 Word에서 고친다. 막히거나 표현을 묻고 싶으면 Claude와 대화한다. Claude는 Magus로 책 전체 맥락(목차·결정·미해결·그 장)을 보고 조언한다.
- Claude의 수정안은 대화로 받고, 아버지가 Word에 반영한다. 아버지가 "Magus에 저장해 줘"라고 분명히 말할 때만 Claude가 Magus 원고를 고친다(서버 규칙 4, #74).
- 떠오른 생각과 읽은 논문은 Magus에 쌓는다(영감·문헌).
- Word에서 고친 원고는 **같은 책의 새 판으로 다시 올린다**(D절). 바뀐 장만 바뀌고, 결정·미해결·쌓아 둔 생각과 문헌은 그대로다.

## 순서(2026-10-05 결정)

1. 운영자 본인 → `default`로 먼저 연결해 6단계를 시험한다(docs/deploy.md 2-1절).
2. 아버지는 그 뒤 **`father`로 따로 추가**한다.
3. 아버지 원고는 **docx 원본을 아버지 받은함에 새로 임포트**한다. `default`의 PDF 임포트본은 옮기지 않는다.

## 0. 7단계 전에 확인할 것

- [ ] **서버에 master 배포**(사용자 승인 대기): 새 파서(표·제N부 들어가며·코멘트 작성자·제목/부제)와 다시 올리기가 서버에 있어야 한다. 절차는 docs/deploy.md "업데이트". 배포 뒤 `/book`에 "원고 올리기"(새 판/새 책 선택)가 보이는지 본다.
- [ ] **받은함 화면 검토**(결정 #56 보완): 사용자가 `/inbox` 업로드 화면을 캡처해 채팅 Claude와 검토한다. 아버지가 혼자 올릴 수 있는지 본다.
- [x] **docx 크기 확인**(결정 #54 보완): 최신본 1.4MB(한도 `MAX_UPLOAD_MB` 50MB 안). 새 판을 받을 때마다 크기를 본다. 넘으면 서버 `.env`에서 올리고 `sudo docker compose up -d`.

## A. 운영자가 할 일

- [ ] WorkOS(**Staging**, 결정 #49)에서 아버지를 **초대**한다(가입은 꺼져 있다). 로그인 방법은 이메일 코드(Magic Auth)다.
- [ ] 아버지가 한 번 로그인하게 한다: `https://magus.lifebookapplication.com/login` → 403 화면의 사용자 id를 받는다.
  - WorkOS 대시보드 Users에서 아버지 id를 찾아도 된다.
- [ ] 서버 `.env`에 `ALLOWED_USERS=<운영자 id>=default,<아버지 id>=father`를 넣고 `sudo docker compose up -d`를 실행한다(`restart`가 아니라 `up -d`).
- [ ] 아버지가 다시 로그인해 `/book`이 비어 있는 것을 확인한다.
- [ ] **비인용 용어 옮기기**: `default`의 book 프로젝트에 넣었던 용어 5개(선하이정·마닐라·유조프카·푸둥·모스크바 회사)는 프로젝트별 파일이라 따라오지 않는다. 임포트한 뒤 아래를 실행한다. 새 판으로 다시 올려도 이 목록은 그대로 남는다.
  ```sh
  sudo docker compose exec -e USER_ID=father magus /app/.venv/bin/magus terms --project-id book --add 선하이정 마닐라 유조프카 푸둥 "모스크바 회사"
  ```
  - 최신본에서는 표 안의 `상트페테르부르크(1703)`가 "미연결"로 잡힌다. 지명이라 같은 방법으로 넣을 후보다(사용자 확인 뒤).
- [ ] 아버지 보고서 답변(음역 추정 등)을 확정할 때는 아버지 책장에 넣는다.
  ```sh
  sudo docker compose exec -e USER_ID=father magus /app/.venv/bin/magus alias <key> <표기>
  ```

## B. 아버지와 함께 할 일

- [ ] **커넥터 등록**: docs/connect-claude.md "아버지용" 1~5를 따른다(컴퓨터의 claude.ai에서 한 번 하면 휴대폰에도 보인다).
- [ ] **docx 업로드**: 브라우저 `https://magus.lifebookapplication.com/inbox` → 원고 docx를 고르고 **올리기**를 누른다.
- [ ] **처음 가져오기**: `/book` → "원고 올리기"에서 받은함 원고를 고르고 **새 책으로 가져오기**, 프로젝트 id `book` → **올리기**. 몇십 초 걸린다.
  - 제목·부제 칸은 비워 둔다. 최신본은 파일 속성에서 제목과 부제를 따로 읽는다. 파일 속성에 제목이 없는 판(4판이 그랬다)이면 파일 이름이 제목이 되니, 그때는 칸에 적는다.
  - 기대(2026-10-06 최신본 로컬 시험, `father-trial`)
    - 제목 "인류가 선택한 진화, 시대가 선택한 도시", 부제 "생존과 번영 그리고 그 이동에 관한 역사", 영문 제목·부제
    - 42장: 35장 + 서장·부 들어가며 2(제2부·제4부)·맺음·부록 1~3
    - 8부: 항온 · 평지와 털 · 밀도 · 잉여생산물 · 지리의 확장 · 유동성 · 기술혁명 · 다음 충격
    - 343,185자(표 37개 포함), 그림 10개는 `[그림 N]`
    - 코멘트 → 미해결 129건(citation 43 · fact 82 · general 4), 작성자는 모두 Claude라 **모두 "AI 확인 요청"**으로 보인다. 장 밖은 참고문헌에 단 2건뿐이다.
    - 참고문헌 337줄 → refs 337, 인용 454회, 미확인 문헌 335편(참고문헌에 없음 3: Brook 2008, Eloundou 2023, Wiessner 2014), 중복 서지 1(IEA 2025 두 번)
  - 다르면 운영자가 리포트를 보고 판단한다.
- [ ] **인용 체크리스트 보기**: `/checklist` → 신호등을 읽는 법을 알려 드린다(🟡 미확인, 🔴 참고문헌에 없음).
- [ ] **미해결 보기**: `/issues` → 🤖 "AI 확인 요청"은 Claude가 원고에 단 확인 요청이라는 것을 알려 드린다. 저자의 메모와 구별된다.

## C. 첫 세션 대본 (Claude에서)

1. **책 지도**: "Magus로 책 지도를 보여 줘"
   - 목차, 미확인 문헌 수, 미해결 수, 판(E1)과 올린 시각이 나온다. "모든 작업은 여기서 시작합니다"라고 알려 드린다.
2. **제12장 인용 점검**: "제12장 인용 중 확인 안 된 것 알려줘"
   - 문헌 목록과 문단 번호가 나온다(최신본 시험: 미확인 37편). 확인할 문헌 하나를 고른다.
3. **논문 1편 등록**
   1. 그 논문 PDF를 `/inbox`에 올린다.
   2. Claude에서 이렇게 말한다: "받은함의 <파일명>.pdf를 문헌으로 등록해 줘. 쓸 부분은 「…」, 이유는 …"
   3. 기대: 그 문헌이 "확인 완료(verified)"로 바뀌고, 그 문헌이 나오는 장 목록이 나온다. `/checklist`에서 🟢로 바뀐 것을 함께 본다.
4. **수정안은 Word에**: "제12장 첫 문단을 더 짧게 다듬어 줘"라고 해 본다. Claude가 수정안을 대화로 내고, Magus 원고는 바꾸지 않는 것을 함께 본다. 고친 문장은 아버지가 Word에 넣는다.

## D. 원고를 고친 뒤 다시 올리기(새 판)

- Word에서 고친 원고 파일을 `/inbox`에 올린다(파일 이름은 달라도 된다).
- `/book` → "원고 올리기"에서 그 파일을 고르고 **이 책의 새 판으로 올리기**, 프로젝트 id `book` → **올리기**.
  - Claude에게 "받은함의 <파일명>을 book의 새 판으로 올려 줘"라고 해도 된다(book_import `new_edition=true`).
- 결과 리포트에서 볼 것
  - 판 번호(E2, E3…), 본문이 바뀐 장과 그대로인 장, 새 장·빠진 장(빠진 장은 지우지 않고 보관), 제목이 바뀐 장
  - 원고 코멘트: 이어진 것, 새로 생긴 것, **해결됐을 수 있음**(원고에서 코멘트가 지워졌거나 걸린 문장이 없어진 것). 자동으로 닫지 않는다. 아버지와 확인하고 닫는다.
  - "Magus에서 고친 뒤 이번 판으로 덮인 장"이 있으면, 그 내용이 Word에 들어갔는지 확인한다(이전본은 Magus에 남아 있다).
- 장 제목이 기존 판과 30% 미만으로 겹치면 다른 책으로 보고 멈춘다. 같은 책이 맞으면 "장 제목이 많이 달라도 같은 책으로 올리기"를 체크한다.
- **"같은 id가 있으면 바꾸기"(replace)는 쓰지 않는다.** 결정·미해결까지 휴지통으로 간다(운영 규칙 #78).
- 시험 결과(로컬, `reupload-trial`): 4판(E1, 코멘트 86) → 최신본(E2)에서 바뀐 장 6만 교체, 기존 미해결 86 유지 + 새 43, 결정·생각 그대로.
- Claude의 책 지도에는 마지막으로 올린 시각이 나온다. 7일이 지나면 Claude가 "그사이 Word에서 고치셨으면 최신본을 올려 주세요"라고 먼저 묻는다.

## 확인할 것(위험)

- 다음 날 같은 대화에서 다시 불러 본다. 로그인을 다시 하라고 하면 운영자에게 알린다(토큰 갱신 문제, auth-provider.md 위험 항목).
- 장을 하나 끼워 넣어 번호가 밀린 판을 올리면, 지금은 같은 번호를 같은 장으로 보고 바꾼다(이전본은 보관, 미해결은 걸린 문장을 따라간다). 리포트의 "제목이 바뀐 장"이 많으면 운영자가 확인한다.
