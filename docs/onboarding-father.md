# 아버지 온보딩 체크리스트 (7단계, 초안)

> **초안이다.** 6단계(운영자 본인 계정 = `default`로 Claude 커넥터 시험)를 마친 뒤 실제 화면을 보며 확정한다.
> 아버지 계정은 `father` 사용자다. 운영자의 `default`(개발용 PDF 임포트본)와 데이터가 섞이지 않는다.

## 순서(2026-10-05 결정)

1. 운영자 본인 → `default`로 먼저 연결해 6단계를 시험한다(docs/deploy.md 2-1절).
2. 아버지는 그 뒤 **`father`로 따로 추가**한다.
3. 아버지 원고는 **docx 원본을 아버지 받은함에 새로 임포트**한다. `default`의 PDF 임포트본은 옮기지 않는다.

## 0. 7단계 전에 확인할 것

- [ ] **받은함 화면 검토**(결정 #56 보완): 사용자가 `/inbox` 업로드 화면을 캡처해 채팅 Claude와 검토한다. 아버지가 혼자 올릴 수 있는지 본다.
- [ ] **docx 크기 확인**(결정 #54 보완): 아버지 docx를 받으면 업로드 전에 크기를 본다. 한도는 `MAX_UPLOAD_MB` 50MB다. 넘으면 서버 `.env`에서 올리고 `sudo docker compose up -d`.

## A. 운영자가 할 일

- [ ] WorkOS(**Staging**, 결정 #49)에서 아버지를 **초대**한다(가입은 꺼져 있다). 로그인 방법은 이메일 코드(Magic Auth)다.
- [ ] 아버지가 한 번 로그인하게 한다: `https://magus.lifebookapplication.com/login` → 403 화면의 사용자 id를 받는다.
  - WorkOS 대시보드 Users에서 아버지 id를 찾아도 된다.
- [ ] 서버 `.env`에 `ALLOWED_USERS=<운영자 id>=default,<아버지 id>=father`를 넣고 `sudo docker compose up -d`를 실행한다(`restart`가 아니라 `up -d`).
- [ ] 아버지가 다시 로그인해 `/book`이 비어 있는 것을 확인한다.
- [ ] **비인용 용어 옮기기**: `default`의 book 프로젝트에 넣었던 용어 5개(선하이정·마닐라·유조프카·푸둥·모스크바 회사)는 프로젝트별 파일이라 따라오지 않는다. 임포트한 뒤 아래를 실행한다.
  ```sh
  sudo docker compose exec -e USER_ID=father magus /app/.venv/bin/magus terms --project-id book --add 선하이정 마닐라 유조프카 푸둥 "모스크바 회사"
  ```
- [ ] 아버지 보고서 답변(음역 추정 등)을 확정할 때는 아버지 책장에 넣는다.
  ```sh
  sudo docker compose exec -e USER_ID=father magus /app/.venv/bin/magus alias <key> <표기>
  ```

## B. 아버지와 함께 할 일

- [ ] **커넥터 등록**: docs/connect-claude.md "아버지용" 1~5를 따른다(컴퓨터의 claude.ai에서 한 번 하면 휴대폰에도 보인다).
- [ ] **docx 업로드**: 브라우저 `https://magus.lifebookapplication.com/inbox` → 원고 docx를 고르고 **올리기**를 누른다.
- [ ] **임포트**: `/book` → 받은함 원고에서 docx를 고르고, 프로젝트 id는 `book` → **임포트**를 누른다. 몇십 초 걸린다.
  - 기대: 35장 + 서장·맺음·부록, 8부, 코멘트 86건, 참고문헌 299줄(미확인 문헌 약 297편).
  - docx는 PDF와 조금 다를 수 있다. 다르면 운영자가 리포트를 보고 판단한다.
- [ ] **인용 체크리스트 보기**: `/checklist` → 신호등을 읽는 법을 알려 드린다(🟡 미확인, 🔴 참고문헌에 없음).

## C. 첫 세션 대본 (Claude에서)

1. **책 지도**: "Magus로 책 지도를 보여 줘"
   - 목차, 미확인 문헌 수, 미해결 수가 나온다. "모든 작업은 여기서 시작합니다"라고 알려 드린다.
2. **제12장 인용 점검**: "제12장 인용 중 확인 안 된 것 알려줘"
   - 문헌 목록과 문단 번호가 나온다. 확인할 문헌 하나를 고른다.
3. **논문 1편 등록**
   1. 그 논문 PDF를 `/inbox`에 올린다.
   2. Claude에서 이렇게 말한다: "받은함의 <파일명>.pdf를 문헌으로 등록해 줘. 쓸 부분은 「…」, 이유는 …"
   3. 기대: 그 문헌이 "확인 완료(verified)"로 바뀌고, 그 문헌이 나오는 장 목록이 나온다. `/checklist`에서 🟢로 바뀐 것을 함께 본다.
