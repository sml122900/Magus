## 사람이 읽는 파일을 원본으로, SQLite는 재생성 가능한 인덱스로
- 날짜: 2026-10-03
- P: 297쪽 책을 LLM과 쓰다가 원고가 두 파일로 갈라졌고, 단일 진실 원천이 없었다. 저자가 직접 읽고 고칠 수 있어야 했고, 나중에 SaaS(Postgres)로 옮길 수도 있어야 했다.
- A: `Store` 인터페이스(Protocol) 뒤에 P0 구현 `LocalStore`를 두었다. 원본은 markdown/json 파일이고, SQLite는 인덱스다. 쓰기는 "파일 먼저(원자적 교체) → 인덱스" 순서로 한다. 스키마 버전이 바뀌면 인덱스를 지우고 파일에서 다시 만든다. 모든 테이블과 쿼리에 user_id를 넣었다. "SQLite가 원본"인 구조와 "인덱스 없는 파일만" 구조를 비교해 버렸다.
- R: reindex 전후 스냅샷이 같다는 테스트, 스키마 버전을 바꾸면 자동 복구되는 테스트, 다른 user_id로는 빈 결과가 나오는 테스트를 포함해 24개 테스트가 통과한다. 마이그레이션 코드는 0줄이다.
- 근거: [docs/decisions/store-interface.md](decisions/store-interface.md), [docs/decisions/front-matter-boundary.md](decisions/front-matter-boundary.md)
- 이력서용 한 문장: 원본은 사람이 읽는 파일로, SQLite는 언제든 재생성되는 인덱스로 설계해 마이그레이션 코드 없이 스키마를 바꿀 수 있게 하고, 저장소 인터페이스를 분리해 SaaS 전환 경로를 확보했다.

## 책 전체 대신 3,000토큰짜리 지도: 우선순위 예산 배분 outline
- 날짜: 2026-10-03
- P: 기존 방식은 장 하나를 고칠 때마다 LLM이 책 전체(약 34만 자)를 다시 썼다(한 대화에서 10번 재생성). 에이전트에게 책 전체가 아니라 책의 지도만 줘야 했다.
- A: `book_outline`이 제목, 목차, 최근 결정 10개, 열린 미해결, 최근 변경 5개만 돌려준다. 토큰 수는 한글 1자를 1토큰으로 보는 보수적 추정을 쓰고, 예산을 우선순위대로 배분한다. 넘치는 항목은 "외 N건"으로 접는다. 책 전체를 반환하는 도구는 만들지 않았다.
- R
  - 1차: 35장·8부·미해결 86건·결정 15건 규모의 가짜 책에서 추정 2,846토큰(예산 3,000)이었다. 그런데 미해결은 7건만 실려, 사람이 남긴 미해결이 코멘트 86건에 묻힐 수 있었다.
  - 2차(구조 변경): 목차는 집계만 싣고, 미해결 전문은 user·agent 출처만 싣는다. 코멘트 유래는 건수 한 줄로 줄이고, 목록은 `book_issues` 도구로 뺐다. 예산 배분은 목차 → 직접 미해결 → 결정 → 변경 순서로 바꿨다.
  - 결과: 같은 규모에 직접 남긴 미해결 16건을 더해도 추정 2,893토큰이고 16건이 모두 실린다(`test_outline_fits_budget_and_lists_every_direct_issue`).
- 근거: [docs/decisions/outline-aggregates.md](decisions/outline-aggregates.md), [docs/daily/2026-10-03.md](daily/2026-10-03.md), `src/magus/book/outline.py`
- 이력서용 한 문장: 34만 자 원고를 다루는 LLM 에이전트의 컨텍스트를 우선순위 기반 토큰 예산 배분으로 3,000토큰 이하의 '책 지도'로 제한했다. 출처(사람/에이전트/기계적 코멘트)에 따라 노출 수준을 달리해, 미해결 102건 중 사람이 남긴 16건을 모두 예산 안에 담았다.

## 인용 게이트: 기억에서 만든 인용을 막지 않고 드러내기
- 날짜: 2026-10-03
- P: 실제 사례에서 인용 약 270개와 참고문헌 약 250편이 LLM 기억에서 생성됐고, 저자는 그 문헌들을 읽지 않았다(Word 코멘트 86개 중 82개가 "확인 필요"). 쓰기를 막으면 초고 흐름이 끊긴다.
- A: 본문에서 인용 표기를 뽑아(괄호 안 다중 인용, 조사가 붙은 한글 저자, 국역 aliases 포함) refs와 대조하고, verified / unverified / unknown으로 나눈다. 장을 쓸 때마다 막지 않고 결과를 돌려주며 장별 미확인 수를 집계한다. verified는 "직접 고른 발췌가 있을 때만" 허용한다. Word 코멘트를 citation/general로 분류하고, 정식 ref key로 refs와 연결한다.
- R: 합성 원고 7개 장에서 미확인 인용 9건을 찾았다(1장 8, 4장 1). 한글 표기 3종(갤러는·갤러·다이아몬드)을 aliases로 영문 key에 연결했다. "서지" 오탐을 문맥 판정으로 없앴다. 완료 기준(ref_check 1장 → ref_add 뒤 verified로 이동)을 테스트로 고정했다.
- 근거: [docs/decisions/citation-gate.md](decisions/citation-gate.md)
- 이력서용 한 문장: LLM이 만든 인용을 차단 대신 '표시·집계·검증'하는 인용 게이트를 설계해, 한국어 인용 표기(다중 인용, 조사, 번역서 표기)를 정식 문헌 key로 해석하고, 실제로 발췌한 문헌만 검증 상태로 올리는 흐름을 구현했다.

## 누가 말했는가: 대화 기록에서 사용자와 AI의 말을 분리 보존
- 날짜: 2026-10-03
- P: 과거 대화를 수동으로 8번 첨부해도 생각이 사라졌고, AI가 제안한 주장과 저자의 주장이 섞였다.
- A: 세 가지 대화 형식(화자 마커, 질문/답변, 인용+요지)을 한 파일 안에서 섞여 있어도 줄 단위로 스캔해 발화로 나눈다. 사용자 발화는 author=me로, AI 발화는 author=ai + parent_id로 저장하고, 분리 실패 구간은 버리지 않고 리포트한다. 검색은 기본 me만, all이면 me를 먼저 보여 주고, AI 결과에는 응답한 질문을 붙인다.
- R: 합성 96쌍 기록에서 me 96 / ai 96, 모든 ai에 parent_id가 있고 서문 1구간을 리포트했다. 질문/답변 10/10, 인용/요지 8/8.
- 근거: [docs/decisions/casper-conversation.md](decisions/casper-conversation.md)
- 이력서용 한 문장: 여러 형식이 섞인 대화 기록을 발화 단위로 나눠 사용자와 AI의 말을 구분해 저장하고, 검색에서 사용자의 주장을 먼저 보여 줘 AI 제안이 저자의 목소리로 둔갑하지 않게 했다.

## 실원고 PDF에서 책의 구조와 검증 대상을 되살리기
- 날짜: 2026-10-03
- P: 실원고는 docx가 아니라 Word '메모 포함' 마크업 PDF(297쪽)였다. 줄마다 따로 된 조각에 문단·제목 정보가 없었고, 한국어는 단어 중간에서도 줄이 바뀌었다. 코멘트 86개는 오른쪽 말풍선에 여러 줄로 흩어져 있었다. 합성 데이터로 만든 파서는 이 원고에서 쓸 수 없었다.
- A: 좌표·글자 크기·들여쓰기로 레이아웃을 복원했다(반복 머리말 제거, 말풍선 단 분리, 한국어 줄 잇기, 글자 크기별 문단 서식 판별, 제목 단계). 서장·맺음·부록은 번호 없는 장으로 만들었다. 인용 추출은 실원고 표기 422개를 조사해 보정했다(발음 부호, 접두어, 한자 저자, 설명 뒤 인용, 한글 음역 → 영문 참고문헌 추정 연결, 지명 오탐 분리). "파싱 실패 0"에 가려진 참고문헌 병합(300→190)을 원본의 독립 지표로 찾아냈다.
- R: 35장·8부·코멘트 86건·참고문헌 299건을 복원했다(완료 기준 전부 충족). 대화 기록 4종에서 me/ai 226쌍을 분리했다(기준 파일 96/96). 고유 미확인 문헌 296건과 참고문헌 누락 2건·미인용 4건을 집계해 '확인 순서' 리포트를 냈다. 실원고 outline은 1,946토큰이다. 테스트 140개.
- 근거: [docs/decisions/realdata-import-calibration.md](decisions/realdata-import-calibration.md), [docs/decisions/citation-matching-realdata.md](decisions/citation-matching-realdata.md), [docs/troubleshooting/pdf-bibliography-merge.md](troubleshooting/pdf-bibliography-merge.md)
- 이력서용 한 문장: 구조 정보가 없는 297쪽 Word 마크업 PDF에서 레이아웃(좌표·글자 크기·들여쓰기)으로 장·부·코멘트 86건·참고문헌 299건을 복원하고, 한글 음역 인용을 영문 참고문헌에 잇는 매칭으로 296개 미확인 문헌의 확인 순서를 산출했다.
